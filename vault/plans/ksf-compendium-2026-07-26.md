## Correction of record

An earlier draft of this file stated the kill switch was INERT, citing SCS C92 from
memory. **That is wrong and is corrected here.** SCS C92 *repaired* the kill switch on
2026-07-12: the digest exists at `~/.claude/knowledge_vault/core/HARD-RULES-DIGEST.md`,
is well under the tool read limit, and the global router resolves to it.

The real defect was narrower. `build_digest` dropped any class with zero rules, and
`PLUGIN-INSTALL` — one of the four classes the global router contracts on — matches zero
of 148 binding rules. So the row vanished from the digest, and `--class PLUGIN-INSTALL`
answered `0 BINDING rule(s). Comply before acting.` at **exit 0**. An unenforced trigger
point was indistinguishable from a clean pass, and a class that is never listed can never
be missed. This is `feedback_zero_cannot_fall` and `PR-COVERAGE-BY-CONSTRUCTION-001` in
the enforcement layer itself.

**Repaired (verified, this session):** contracted-but-empty classes stay in the digest
with an explicit `0` and are named under `## CONTRACTED BUT UNENFORCED`; the CLI returns
exit 3 for them; an import-time guard raises if a rename ever drops a contracted class
out of `TRIGGER_CLASSES`. Digest 2,154 → 2,409 B (cap 4,096). `ENFORCEMENT_PASS=19/19`,
exit 0. The remaining corpus gap (authoring plugin-install rules, or retiring the
trigger) is an Owner call recorded in `vault/OWNER_QUEUE.md` item (a).
