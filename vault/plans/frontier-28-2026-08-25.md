## 4. Phase 1 — closed

`_discover_families()` promoted **every** directory under `vault/knowledge_base/` to a
parent, reading the working tree, with no record of when a directory arrived or whether
anyone sealed it. The previous mission wrote `vault/knowledge_base/ucr_cif/`; by the next
session the engine was scoring new proposals against `KB-UCR-CIF`. The contamination was
not a transient bad read — it had been **institutionalised into the engine's family
table**, where it would price every future proposal.

`modules/duplicate_to_advantage/provenance.py` adds two boundaries, and the weaker one is
pinned by a gate *because* it is insufficient:

- **Tracked-ness** catches an audit whose output is not committed yet. It would **not**
  have caught `ucr_cif`, which was committed the same day. Recorded as
  `V-D2A-PROV-TRACKED-IS-NOT-ENOUGH` so the half-fix cannot later be mistaken for the fix.
- **A declared cutoff** (`PP_AUDIT_CUTOFF`, ISO date or any git revision) closes it. A
  family first committed after an audit began is that audit's output *relative to that
  audit*. Declared, never sniffed — an auditor that infers its own start date can infer a
  convenient one.

Measured, both directions: cutoff `a3a66a8^` → `_discover_families()` 27 → 26, KB-UCR-CIF
dropped; cutoff `bc81ca7` → 27, retained, because `ucr_cif` genuinely predates this audit.

Fail-open is directional: unknown provenance is treated as sealed, the behaviour before
this module existed. Excluding a real parent yields a false CREATE (build a duplicate);
admitting a false parent yields a false OWNED. The estate's base rate — fifteen
consecutive mega-corpus proposals measured majority-owned — makes false CREATE the
costlier error, so the fallback leans away from it, and reports the degradation.

`tools/test_d2a_provenance.py` → 6/6 ×3, hermetic. `test_duplicate_to_advantage.py` →
39/39, no regression. Interaction with `vault/specs/d2a-family-wiring.md` ("engine not
touched"): that spec froze the engine's *public surface* for its rollback story; no
signature of `run()` / `run_family()` / `detect_duplicate()` changed here.

**Session failure captured** (§47): the first version of the new suite probed for a bare
`git`, which is absent from this host's non-interactive PowerShell PATH, so every gate
skipped and the suite printed `0/0 PASS` at exit 0 — a green run asserting nothing, the
same false-negative class the file exists to catch. Fixed by reusing the resolver of the
code under test.
