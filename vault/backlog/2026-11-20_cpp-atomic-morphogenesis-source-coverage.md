## M01. Three levels of developmental inheritance

**Generation I: inherit what works.** New projects receive only the applicable verified traits and capabilities, including failure and proof contracts, not blindly copied architectures.

**Generation II: inherit how to reach maturity.** Reuse proven sequences of research, design, verification and migration. Eliminate avoidable work while distinguishing genuine later discoveries/hindsight.

**Generation III: inherit when/how to transform.** Project architecture has a conditional **Validity Envelope**; detect when real operating conditions invalidate assumptions and propose measured, reversible minimal adaptation.

**Central architectural correction:** the institution should afford complex change, while individual products remain as simple as their actual requirements permit. "Minimum Sufficient Maturity" is not minimal quality; it means full applicable guarantees and no speculative infrastructure rent.

## M02. Traits, implementations and proofs must be separate

- **Trait:** externally meaningful product/system property or guarantee (durability, no unauthorized effects, accessible journey, offline availability, compatibility).
- **Implementation:** mechanism fulfilling it under an envelope (e.g., local atomic file, PostgreSQL transaction, state machine with external store).
- **Proof:** an assertion/evidence/verifier binding showing property for exact artifact, scope/version/environment, possibly only one failure model.

**Trait Conservation:** a replacement architecture can change every implementation detail while preserving active approved traits. New architecture must prove preserved traits on its own artifact/runtime. Traits may be retired only with deliberate product/governance decision and full consumer impact.

**Migration regression test:** replace storage with a new system that passes happy-path tests but loses confirmed writes during crash or duplicates effects; migration cannot be SEALED. Distinguish old "demonstrated", new "demonstrated"/"unrun"/"contradicted"/"decision required."

## M03. Developmental State Vector, not arbitrary maturity score

Logical state `D_t = (Usage, State, Authority, Execution, Failure, Distribution, Lifecycle, Evidence)` with optional observed performance/business dimensions tied to actual need.

| Axis | Progressions that matter | Caveat |
| --- | --- | --- |
| Usage | individual → team → many customers | Growth alone not proof multi-region needed |
| State | ephemeral → durable → shared → replicated | Durable local state may remain optimal |
| Authority | one owner → multi actor → external third parties | Scope and tenancy require real contracts |
| Execution | synchronous → async → supervised → autonomous | More autonomy = stronger effect requirements |
| Failure model | local reversible → recoverable → money/data → irreversible | Choose proof/approval proportional to consequence |
| Distribution | single process → processes → hosts → regions | Presentation on many devices ≠ many writers |
| Lifecycle | prototype → production → prolonged operation | Need measured health/rollback and compatibility |
| Evidence | static → integration → runtime → longitudinal | Higher evidence type does not mechanically cover all properties |

**Maturity Lag:** observed preconditions invalidated while implementation still relies on them, without adequate mitigation.
**Maturity Overshoot:** unneeded complexity imposes meaningful maintenance/failure/cost without currently justified value or option value.
Do not use file count/module count as a maturity score. Maturity is multidimensional; a strong local tool may rationally omit multi-region traits.

## M04. Software Birth Record (projection, not a new mutable SSOT)

A newly created significant product can receive a **Software Birth Record** derived from repo, mission, user decisions and CPP evidence:

| Field | Required contract |
| --- | --- |
| Product Identity | Stable namespace and primary promises |
| Mission Contract | Exact Owner intent, audience, quality/acceptance |
| Environment Fingerprint | Stack, versions, host/runtime, dependency/setup reality |
| Developmental State | Observed vector and explicit UNKNOWN components |
| Validity Envelope | Premises under which chosen architecture is sufficient |
| Applicable Traits | Institutional guarantees required now |
| Latent Traits | Known institutional capabilities intentionally not active |
| Excluded Traits | Evidence-backed not-applicable/rejected |
| Evidence Obligations | Target-appropriate tests, confidence and proofs |
| Authority Model | Read/write/spend/send/deploy/delete + human boundary |
| Evolution Boundaries | Conditions requiring architecture re-evaluation |
| Lineage References | Prior capabilities/traits/proofs from parent projects |
| Unknown Frontier | Unanswered questions and resolution experiments |

**Inheritance state vocabulary:** ACTIVE_INHERITED, LATENT_INSTITUTIONAL, LOCALLY_REQUIRED, REQUIRES_TRANSITION, NOT_APPLICABLE (with reason), UNRESOLVED (honest).

A project inherits **requirements and capability availability**, not the runtime cost of all known future capabilities. "Can upgrade later" is credible only with preserved options, migration proof and risk acceptance.

## M05. Developmental Compilation & Search Space Collapse

Initial candidate solutions `A0` are constrained to viable subset `A_valid = {a in A0 | demonstrated constraints hold}`. Pruning candidates requires a dated cause and applicability proof (incompatibility, permissions, economic dominance, prior counterexample); NEVER prune on semantic proximity or fashionable architectures.

The compiler maps:
- Deterministic syntax/schemas to parser;
- existing known contracts to verified rules/tests;
- version/platform facts to signed/observed constraints;
- comparative economics to measured candidates;
- design/context to creative operator + suitable review;
- novel questions to experiment;
- protected irreversible effects to actual authorization owner.

**False-prune test:** viable alternative eliminated by an overgeneralized law becomes a red control; user meta/question intent cannot awaken project-construction family without relevant build intent.

## M06. Trait Lineage Graph: multi-parent, not repository fork graph

Nodes: Product, Trait, Capability, Proof, Work Class, Transition, Failure Pattern, Counterexample, Institutional Rule, Consumer. Edges: derived_from, depends_on, applies_to, refuted_by, implemented_by, evaluated_by, inherited_by, superseded_by, invalidates, used_in.

Use `modules/graphify` plus Knowledge Vault, UCR-CIF/Tower and Goal events as *projections*. Do not invent a second editable graph authority. Reference source hashes, evidence, license/security and access controls. A raw private client transcript must never auto-propagate to another tenant; promote safely generalized method, subject to rights.

**Epistemic invalidation:** premise P invalid ⇒ dependent proof C may need rejudgment, not necessarily C false. Retain contradictory observations with their scope, not silent dedup to a universal claim.

## M07. Continuous Morphogenesis: pressure and validity envelope

On actual environment/mission delta, derive an architectural pressure event:
`pressure_id, product_id, dimension, before, after, source, evidence, claimed_vs_observed, affected_assumptions, urgency, reversibility, candidate_transitions, status`.

**Important:** Owner roadmap statement is a *future intention*, not observed production state. Recompute only affected assumptions, proofs and consumers; no full institutional scan unless index is untrusted or contract broad.

**Eight real maturity boundaries (source):**
1. single writer → multiple writers: coordination/CAS/fencing;
2. ephemeral → durable: identity/persistence/replay/recovery;
3. sync → async: in-flight/expiry/confirmation;
4. present human → autonomous: delegated bounded authority/proof;
5. local → distributed: causal ordering, partial failures, writer ownership;
6. single user → multiuser: authorization/isolation/privacy/concurrency;
7. prototype → production: operational checks/compatibility/rollback;
8. internal dependency → external provider: unavailability/contracts/versioning/reconciliation.

Only add machinery when the boundary materially changes current guarantees. Multiple frontends do not imply distributed writes; PostgreSQL may already satisfy multi-writer need.

**Hysteresis:** avoid oscillation on transient signals; use relevant trend, reversibility, severity and decision cost. No one global traffic threshold. Immediate high-severity safety risks bypass a slow trend review.

## M08. Incremental Developmental Recompilation (IDR)

Pipeline: OBSERVE → CLASSIFY → INVALIDATE assumptions → RESOLVE active traits → RETRIEVE verified transformations → COMPARE viable options → TRANSITION via authorized plan → VERIFY/LEARN. Change delta `Δx` should trigger `AffectedClosure(Δx)` under real dependency index, not a global model debate.

Index: premise→contract, contract→capability, capability→consumers, trait→proof, event→obligations, rule→baseline, version→compatibility, state→runtime conditions.

**Unknown edges** widen proof scope or report an explicit gap. Never claim O(Δ) cost with an incomplete or self-justifying graph. Measure rejudged nodes, missed consumers, wrong wakes and full-versus-affected verification quality.

## M09. Developmental Metamorphosis Contract and migration steps

For high-impact architectural transitions preserve:
- product identity/promise; existing applicable traits and newly needed traits;
- explicitly approved removed traits;
- old/new state + environment and toolchain/behavior versions;
- data conversion, compatibility and proofs;
- authority/writer topology before/during/after;
- coexistence and cutover condition;
- irreversibility boundary and honest rollback constraints;
- monitor health, effects, recovery, timeouts, permissions and incident handoff.

**Nine migration phases:** M0 Characterize → M1 Specify → M2 Prepare → M3 Migrate → M4 Coexist when needed → M5 Cutover → M6 Observe → M7 Retire → M8 Capitalize. These are risk-scoped, not mandatory ceremony for trivial edits.

**Critical rule:** a backup is not proof reversible when new consumers, external effects or post-cutover writes make restoration unsafe. Distinguish backward migration, forward repair and Owner-only irreversible gate.

## M10. Evolution Insurance and Software Optionality

Compare **anticipate future complexity now** vs **stay simple with proven migration path** by total verified lifecycle cost: current complexity rent + operation/maintenance + risk vs simple build + probability of future transition × migration cost + delay risk. Do not invent transition probabilities, future revenue or "10x scale" based solely on repo.

Preserve valuable options (interface boundary, migration-safe schema, separable effects) if the carrying cost and irreversibility warrant them; reject optionality theater (abstract everything "for flexibility").

**Evolution Insurance** is not magical insurance against future requirements; benefit grows only with empirically successful, reusable migration patterns and honest risk ceilings.

## M11. Institutional metabolism: decision extinction + Work Class compilation

**Decision Extinction:** after valid repeated evidence, move solved cognition from open model reasoning into certified deterministic lookup/primitive. Detect wrong reuse and deopt safely. A creative/strategic judgment may stay irreducibly cognitive.

**Work Class Signature:** intent, state topology, authority topology, failure model, platform contract, input/output contract, lifecycle, evidence class, economics, novelty. Distinguish shared invariants from variant parameters (e.g. PostgreSQL vs filesystem; single vs multiple writers).

Promotion trajectory: observed experience → explanatory causal pattern → contract/counterexample → locally tested method → transfer holdout → reachable routing → beneficial real use → institutional standard or reusable code (when economics support it). Do not conflate "a new SKILL.md" with a capability; executable/typed validator may supersede prompt text.

**Semantic Singleflight:** share genuinely equivalent research/proofs/tasks only when semantic obligation, relevant inputs, dependency fingerprint, environment, authorization scope, proof requirement, freshness and tenant privacy match; otherwise separate jobs. Event ID ≠ effect ID ≠ semantic-equivalence fingerprint.

## M12. Knowledge, information value, unknown-unknowns and retirement

Knowledge: original observed fact vs reported claim vs tested hypothesis vs verified application. Store contradictory scoped evidence and causal invalidators. A stale proof triggers affected revalidation; never retroactively claim a negative fact without evidence.

Value of Information (conceptual): anticipated decision-loss reduction from an experiment minus its execution cost. Prefer tests that differentiate rival hypotheses over extensive undirected retrieval. Numerical weights require calibration/data; ordinal comparisons acceptable.

Boundary / contradiction / novelty probes reveal mistaken assumptions, but bounded experiment budget and progress criteria prevent autonomous research loops. Three rounds with no new evidence/decision movement ⇒ stop, hand back named unknown.

Retirement: measure invocation, value, cost and exceptional safety duties; propose deactivation of unused/negative-ROI capabilities via existing retirement owner; preserve history and never auto-retire safety floors solely for low usage.

## M13. Maturity Ledger and prediction calibration

Maturity Ledger = derivable projection of real product state, not a manually maintained parallel registry. Fields: actual developmental vector, active envelopes, invalidated assumptions, applicable baselines, active/latent traits, migration candidates, evolution receipts, unresolved questions.

Evidence rungs: DECLARED, STRUCTURAL, EXECUTED, OPERATIONAL (each bound to its actual probe). Do not convert a declaration of "multi-region ready" into operational fact by a static regex.

Track transition precision/recall, false maturity cost, late maturity cost, migration reuse, trait regressions, developmental compression and correctly rejected transitions. An accurate "no migration needed" is positive decision quality.

## M14. Full workstation developmental example (source preserved)

**A** Local tool: single machine, local state, no speculative distributed OS. **B** Crash-survivable work: durable identities + persistence + recovery, still may stay local. **C** Multi-device workstation: desktop/laptop/mobile as presentation/control clients of one logical workstation; do not infer multiple writers. **D** Multi-node execution: authority, lease/fence, state capsules, provenance, careful distribution between laptop/GEX44/VPS. **E** Bounded autonomous execution: per-effect permissions, budgets, cancel/resume, independent proof, idempotency/recovery. Every transition has entry preconditions, trait conservation, proof and exit condition. Inherit this trajectory, not entire final architecture, in unrelated products.

Autonomy ladder: MANUAL → ASSISTED → SHADOW → BOUNDED → SUPERVISED → BROADER only where real authority/proof supports it. "Full autonomous" is not a global toggle and does not include credential issuance, self-modifying gates or unconstrained spending.

## M17. Closure criteria for this domain

Do NOT declare "software morphogenesis" ready from a document or static code scan. Minimum pilot:
- baseline exact real product state;
- one observed invalidated premise or measured complex-to-simple opportunity;
- trait inventory with applicability and proof;
- two or more viable alternatives evaluated without invented traffic/ROI;
- a reversible, scoped authorized change;
- actual tests of conserved and new traits, with negative controls;
- measured cost/risk difference where possible;
- follow-up on a separate project/replay without hindsight contamination;
- result classified SUCCESS/FAIL/INSUFFICIENT and retained evidence;
- decision on pattern's institutional applicability and any overdue retirement.

A valid no-op (architecture sufficient now) or deferred migration with justified evidence may count as a **successful decision**, not as a shipped new system.
