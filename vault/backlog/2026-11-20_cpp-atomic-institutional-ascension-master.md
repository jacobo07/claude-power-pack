## 1. North Star and principles

Transform CPP from a broad agent framework into a **verifiably compounding engineering institution** in which existing experience lowers future avoidable work while maintaining strong outcome proof, security, authority and maintainability.

- Generation 1: code assistant. Generation 2: agent framework. Generation 3: reusable engineering platform. Generation 4: compounding engineering institution.
- Developmental inheritance 1: **inherit what works**. 2: **inherit how to achieve maturity**. 3: **inherit when and how architecture must evolve**.
- Product-level design: **Minimum Sufficient Maturity**. Institution owns change capability; individual projects carry only justified current complexity.
- **Atomic Verified Transition (AVT):** a minimal semantically complete state change with intent, preconditions, authority, effect, before/after state and proof.
- Repeated Work Classes evolve from observations → demonstrated patterns → reusable components → deterministic primitives where eligible; new novelty triggers bounded cognition instead of forced reuse.
- Every milestone distinguishes Product, Reliability, Intelligence, Economic and Developmental Deltas. Unmeasured benefit is UNKNOWN; a safety correction need not claim immediate savings.
- Context is ephemeral working memory; durable state/proofs/knowledge live below the model. Scale cognitive spend with irreducible uncertainty, not institutional history, duration or goal count.
- Eliminate invalid branches of the search space with evidence; never prune valid options using guessed or overgeneralized applicability.
- Preserve traits during architecture migrations; architecture evolves when real conditions invalidate assumptions, not because a hypothetical future seems attractive.
- Deletion, deactivation, retirement and deoptimization of bad or duplicative capabilities are positive outcomes when supported by proof.

## 4. Constitutional safety and correctness invariants

1. **Reality > assumptions**: NOT_RUN/UNCHECKED/UNJUDGED/UNKNOWN are never silently PASS or NOT_APPLICABLE.
2. Observation, claim, hypothesis, obligation, decision, transition, effect, proof and capability are different kinds of information; the distinction survives conversions.
3. Every protected effect must be authorized at the actual resource boundary; a lease without enforced fence is not mutual exclusion.
4. Provider success, queued command and process exit 0 do not demonstrate postcondition success.
5. Independent judge binds verdict to exact source/tree, revision, relevant runtime/assumptions and gate version.
6. Any baseline change which weakens a check, shortens its measured population, skips an assertion or rewrites an oracle needs explicit controlled authority and negative controls.
7. External docs, skills and GitHub repositories are untrusted input, not privileged execution instructions; audit licenses and side effects before adaptation.
8. Known waiting never requires a resident model; recovery is durable and result ambiguity is not permission to retry blindly.
9. Never promise exactly-once for arbitrary remote providers; use supported idempotency + effect receipt, or reconcile/stop with Owner.
10. Work-class transfer requires applicability and negative cases; a useful pattern need not become a global rule.
11. Quality, safety, correctness, privacy, authority and proof floors must not be traded away for token savings.
12. An architecture may be intentionally local, single-writer, simple or non-autonomous if its real mission permits it.
13. Protected private/client evidence is not automatically distributable to other projects; transfer generalized lessons with provenance and data-minimization.
14. No self-updating rule, config or evaluator bypasses Owner/privileged approval; promotions and retirements are proposals until separately authorized where required.
15. Immutable histories are not identical to operational state snapshots; model identity, causal ordering, retained provenance and replay compatibility.
