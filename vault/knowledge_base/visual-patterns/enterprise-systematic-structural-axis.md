# Enterprise systematic surface (structural axis)

Decision: this style is **not** a new aesthetic family F11. `modules/cdio/scorer.py` KNOWN_FAMILIES stays F1..F10, the font
sanction and `test_cdio_f10` are untouched. Reason (7-system bench, `vault/programs/bcap-2/saas-styles/ENTERPRISE_BENCH.json`):
palette is near F1 (white ground, restraint), and it separates from F4 (dark, categorical palette) and F10 (one task per
screen) by STRUCTURE: dense desktop record flows (forms, tables, processes). Treat it as an axis a surface declares,
judged by the existing CDIO dimensions under the family the palette resolves to.

## Invariants that survived 7 systems (measured, light theme, demo components)
- ground white or near-white 7/7; body text 12-14px (13-14 in 6/7); ink contrast 6.69-16.86:1 (above the 4.5 floor)
- table header never uppercase; distinguished by weight (>=600 in 4/7) and/or a faint tint (1.00-1.32:1)
- no zebra in 5/7; 1px divider at 1.14-2.15:1 where measured
## Not an invariant
- row height (32-55px, median 45): density is a mode each system offers. The mode itself was not measured.

## Declared, not claimed
- Substitute evidence: demo components, not logged-in products. Dark theme, controls, accent and Lightning header/divider unmeasured.
- Axis fires only for dense desktop record work; a dashboard where charts lead stays F4, one task per screen stays F10.
- Styles 1 (dark monochrome rules 5-6) and 2 (conversational AI, 403 access) of the same backlog remain unresolved.
