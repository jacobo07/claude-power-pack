## 1. Bazel Remote Execution API (REAPI v2)

Source: github.com/bazelbuild/remote-apis `build/bazel/remote/execution/v2/remote_execution.proto`, branch main @ `adbf4a27c86fbea4a37637a6cbcacef372406fe7` (2026-09-22, "add Namespace Bazel Cache and Remote execution (#385)"). SPDX: Apache-2.0.

### 1.1 Extracted definitions (near-verbatim from the proto)

- **Digest {hash, size_bytes}.** hash = lowercase hex padded to hash length. Why size is part of identity: "the server needs to know the size of the blob it is about to work with prior to starting an operation with it, such as flattening Merkle tree structures or streaming it to a worker." Corollary (inference): size is a cheap pre-hash truncation detector and a cap/quota input before reading a byte. Proto digests are over a canonical encoding: "Fields are serialized in tag order. There are no unknown fields. There are no duplicate fields."
- **Directory canonical form.** "In order to ensure that two equivalent directory trees hash to the same value, the following restrictions MUST be obeyed": files/dirs/symlinks each sorted "by code point, equivalently, by UTF-8 bytes"; "Each child in the directory must have a unique path segment"; node_properties sorted by name. FileNode{name, digest, is_executable, node_properties}; DirectoryNode{name, digest of child Directory}; SymlinkNode{name, target relative to parent or absolute starting with `/`}. NodeProperties carry `unix_mode` and `mtime` optionally: mode/mtime are OPT-IN identity, not default.
- **Tree** = root Directory + all child Directory protos in one message.
- **Command**: arguments; environment_variables "MUST be lexicographically sorted by name"; output_paths supersedes deprecated output_files/output_directories; working_directory "must be a directory which exists in the input tree"; output_node_properties sorted; Command.platform deprecated for Action.platform.
- **Action**: command_digest ("MUST be present in the CAS"), input_root_digest, timeout (part of the digest: "two Actions with different timeouts are different"), do_not_cache, salt ("place this Action into a separate cache namespace"), platform.
- **ActionResult**: output_files / output_directories / output_symlinks (one entry per requested path that existed), exit_code, stdout_digest/stderr_digest (+ optional inline), execution_metadata = ExecutedActionMetadata{worker, queued_timestamp, worker_start/completed, input_fetch_start/completed, execution_start/completed, output_upload_start/completed, virtual_execution_duration}.
- **ActionCache**: "Implementations SHOULD ensure that any blobs referenced from the CAS are available at the time of returning the ActionResult." ExecuteResponse: "If status has a code other than OK, the result MUST NOT be cached."
- **CAS / FindMissingBlobs**: client asks which digests are absent before uploading; "Servers SHOULD increase the lifetimes of the referenced blobs if necessary"; lifetime "SHOULD be long enough to allow for newly-added and recently looked-up entries to be used in subsequent calls". "Servers MUST behave as though empty blobs are always available." Missing inputs at Execute -> PreconditionFailure, one Violation type MISSING per blob.
- **ExecutionStage**: UNKNOWN(0), CACHE_CHECK(1), QUEUED(2), EXECUTING(3), COMPLETED(4).
- **DigestFunction**: MD5, MURMUR3, SHA1, SHA256, SHA384, SHA512, VSO, BLAKE3, SHA256TREE; if unset, server SHOULD infer from hash length.

### 1.3 REAPI failure-corpus candidates (Bazel latest release 9.2.0, 2026-07-13, Apache-2.0)

- **F-REAPI-1 — stale AC hit after CAS eviction.** tuist/tuist#11221 (opened 2026-06-10, open, p1): Kura REAPI "GetActionResult returns cached action results without verifying that referenced output blobs still exist in the CAS"; a fixed-capacity segment ring deleted blobs; Bazel failed with "Lost inputs no longer available remotely", unrecoverable without `clean --expunge`. Proposed fix: "If any are missing, return NOT_FOUND (and ideally delete the stale AC entry)", plus touch-on-access and an age-gate (AC entry time vs oldest segment). Abstraction: **an index that outlives its referents turns eviction into a poisoned hit.**
- **F-REAPI-2 — client-held digests for evicted outputs.** bazelbuild/bazel#10880 (2020-03-01, closed not planned) and #8250 (2019-05-07, open P2): with `--remote_download_outputs=toplevel` Bazel holds digests of intermediates it never downloaded; eviction -> "does not exist remotely". Ideal fix named: re-execute the producing action transitively; accepted interim: "fail with a meaningful error message". Abstraction: **a digest you hold is not a blob you hold; "known heads" can be a stale belief.**
- **F-REAPI-3 — poisoning by exit-0 malformed output.** bazelbuild/bazel#4276 (2017-12-11): "one of the action exits 0, but the output is malformed", seen in production on CI with disk exhaustion; later hits reuse it. Bazel mitigation for the neighbouring class (inputs modified mid-build): `--experimental_guard_against_concurrent_changes`. Abstraction: **exit code is not evidence of a valid output; address the result only after it is verified.**

UWCP exposure: F1/F2 = the node's "known heads" + stage dirs deleted on harvest (§10): the dispatcher may build an incremental bundle against heads the node has since dropped or never received (failed harvest). F3 = a capsule captured while the agent is still writing, or on a disk-full node.

## 2. Dagger

Repo github.com/dagger/dagger, latest release **v0.21.9 (2026-08-26)**, SPDX Apache-2.0. Sources: docs.dagger.io/api/filters (fetched 2026-09-25), pkg.go.dev `github.com/dagger/dagger/engine/telemetryattrs` @ v0.21.9, pkg.go.dev `dagger/core` + `dagql`, PRs #14265, #14300 (merged 2026-09-24), #14200.

- **Content naming.** Engine sits on BuildKit (LLB ops, content-addressed layers). On top, dagql caches by the **call.ID digest** (a *recipe* digest: the call graph that produced a value). `MakeDirectoryContentHashed` rewrites a Directory's ID digest to a **content hash**, so "all directory instances with the same content" dedupe; "a file from a lazy parent has no content digest, so its cache key is its recipe". PR #14265 "content-preferred digests": recorded content "is a producer-defined semantic identity, not necessarily a byte checksum". Class: **DATA MODEL (recipe digest vs content digest).** UWCP mapping: a capsule has both — recipe = (base commit + bundle + diffs), content = the resulting tree id. §10 verify should compare CONTENT, and keep recipe for provenance. Status: partial (manifest lists both kinds of inputs but does not name the distinction). Falsify: two different recipes (commit-then-diff vs diff-only) yielding the same tree must verify EQUIVALENT.
- **Explicit inputs / host uploads.** "Dagger Functions are not aware of the host filesystem, so they cannot automatically read exclusion patterns from existing .dockerignore or .gitignore files." Pre-call `ignore` patterns (gitignore syntax, order-significant: `"**","!**"` includes all, `"!**","**"` excludes all) filter BEFORE upload; post-call include/exclude after. `defaultPath` resolves relative to the git repo root. Uploads are incremental: "Subsequent calls ... will only upload files that have changed". Class: **INVARIANT (explicit allowlist at the boundary, never inherited from ambient ignore files).** UWCP mapping: §10 "allowlisted untracked tar" — covered in principle. Falsify: a new untracked file matching nothing in the allowlist but NOT gitignored must be excluded; a `.gitignore` edit alone must not widen the tar.
- **OpenTelemetry.** Engine emits OTel spans/logs natively (TUI + Cloud are OTel consumers), and can act as an OTLP receiver for processes in pipelines (issue #10190); BuildKit overrides user `OTEL_EXPORTER_OTLP_TRACES` inside containers (issue #8605). Attributes observed: `dagger.io/dag.digest` (renders a log record under the call that produced the digest), `dagger.io/dag.call.digest` (PR #14200, filterable call digest on payload logs), progress attrs `dagger.io/progress.item|current|total|unit` ("Zero or absent means the total is unknown"), cache facts as OTel log records `dagger.io/cache.fact` (kinds result/identity/deps/retention/part/removed/...), `.seq`, `.version`, `dagger.io/cache.result.id` (PR #14300). Class: **DATA MODEL (reference).** UWCP mapping §16 observability: put the capsule digest and epoch key as span attributes; progress "absent total = unknown" matches the UNKNOWN-is-not-zero doctrine. Status: gap/optional.
- **Cache-facts stream with retention + removed-with-reason.** Class: **ALGORITHM (reference).** UWCP: retention events (capsule dropped, why) as an append-only log, so "missing because retained-out" is distinguishable from "missing because corrupt". Falsify: after retention prunes capsule k, verify(k) must say "retired by retention", not NON_EQUIVALENT.
- **Disposition: REFERENCE ONLY.** Adopting Dagger means a BuildKit engine daemon per node plus its own cache/GC; UWCP's unit of work is an agent session, not a container DAG. Adopt two concepts at zero dependency cost: recipe-vs-content digest naming, and explicit-allowlist-before-upload.

## 3. Kopia and restic

### 3.1 restic
Repo github.com/restic/restic, latest release **v0.19.1 (2026-07-05)**, SPDX BSD-2-Clause. Source: `doc/design.rst` on master (fetched 2026-09-25), manual "Working with repositories" (stable), issue #2715.

- Layout: `config`, `data/` (packs, prefix-sharded), `index/`, `keys/`, `locks/`, `snapshots/`, `tmp/`. "A storage ID is the SHA-256 hash of the content stored in the repository" (i.e. of the encrypted file); blob ID = "SHA-256 hash of the plaintext blob". Encryption AES-256-CTR + Poly1305-AES MAC over ciphertext: `IV || CIPHERTEXT || MAC`. **restic blob IDs are UNKEYED SHA-256 of plaintext** (contrast Kopia). DATA MODEL.
- Pack: `EncryptedBlob1 || ... || EncryptedBlobN || EncryptedHeader || Header_Length(4 LE)`; header entries = type + encrypted length + plaintext hash. Pack is self-describing so the index can be rebuilt from packs (`repair index`). ALGORITHM. UWCP mapping: a capsule's parts should be self-describing too (each part carries its own digest+role header, or the manifest is reconstructible from the part set) — partial; falsify: delete the manifest, can the part set still be identified or at least refused?
- Index files carry `supersedes` (IDs of index files replaced by this one) — an append-only compaction record. DATA MODEL.
- Tree blob = JSON nodes sorted by name: name, type, mode, mtime/atime/ctime, uid/gid, user, inode; files `content` = ordered list of blob IDs; dirs `subtree`; symlinks `linktarget` or `linktarget_raw` (base64 for non-UTF-8). Snapshot = time, tree, paths, hostname, username, uid/gid, tags, parent, `original` when metadata rewritten. **Snapshot identity therefore includes mtime/inode — a backup identity, not a content identity.** ANTI-PATTERN for UWCP verify (would make every checkout NON_EQUIVALENT); fine for provenance.
- CDC: Rabin fingerprint over a 64-byte sliding window, blobs 512 KiB min / 8 MiB max / ~1 MiB average; "An irreducible polynomial is selected at random and saved in the file config ... so that watermark attacks are much harder." ALGORITHM — **REJECTED for UWCP**: capsules are small, deltas are already expressed as git bundles/diffs; CDC buys dedupe across capsules that git objects already give.
- Locks: exclusive (one, blocks all) vs non-exclusive (many); stale after 30 min; refreshed every 5 min; same-host liveness by signalling the PID. "Only the prune operation removes data from the repository"; it takes an exclusive lock; "A pack must be removed from the referencing index before it is deleted." INVARIANT.
- **GC race (restic #2715, opened 2020-05-01, closed via PR #3569):** "Incorrectly removing a lock file can cause everything ... from crashing commands, incomplete indexes to a newly created snapshots that misses most of its data" — i.e. backup and prune ran in parallel after a lock was judged stale; prune saw the backup's new-but-unindexed blobs as unreferenced and deleted them. Fix direction: abort when the lock disappears unexpectedly, verify lock possession before creating the snapshot, abort if refresh does not succeed within 30 minutes. FAILURE PATTERN.
- Integrity: default `restic check` verifies structure; "does not verify that the actual pack files ... are unmodified, because doing so requires reading a copy of every pack file"; `--read-data` reads all; `--read-data-subset n/t | x% | 50M`. TEST PATTERN: a cheap structural verify and an expensive content verify are different verdicts, and a sampled content verify is a third. UWCP: §10 verify should report which it did (structure-only = at best UNKNOWN on content). Status gap; falsify: flip one byte inside a part without changing its size — structure verify must not return EQUIVALENT.

### 3.2 Kopia
Repo github.com/kopia/kopia, latest release **v0.23.1 (2026-06-16)**, master @ `1d4d45a27486cfe5362887d72c047c8940d7bee2` (2026-09-25), SPDX Apache-2.0. Sources: kopia.io/docs/advanced/architecture, /maintenance; `repo/hashing/hashing.go`, `repo/splitter/splitter.go`, `repo/maintenance/maintenance_safety.go` on master; issue #5371.

- Layers: BLOB storage (immutable; prefixes `p` data packs, `q` metadata packs, `x` indexes, plus `n`/`_log`), content-addressable block storage (packs 20-40 MB + index), object storage (large objects via indirect JSON, `I` prefix), label-addressed manifests (snapshots/policies as `key=value` labelled JSON). DATA MODEL.
- **Content ID = keyed hash**: `return hmac.New(hf, p.GetHmacSecret())`, `DefaultAlgorithm = "BLAKE2B-256-128"`. Why keyed (inference consistent with the code and restic's watermark note): with an unkeyed plaintext hash, anyone who can list the store can confirm "this repo contains file X" by hashing X; an HMAC with a repo secret makes IDs unlinkable to plaintext and prevents cross-repo correlation. Encryption AES256-GCM-HMAC-SHA256 or CHACHA20-POLY1305-HMAC-SHA256. INVARIANT (for untrusted stores). **UWCP mapping: REJECTED for the capsule** — the stores (VPS staging, GEX44 stage dir) are our own and the capsule must be verifiable by any party that holds it without a secret; git blob ids are unkeyed by necessity. But note the exposure: capsule manifests list blob ids of files, which are linkable to plaintext; acceptable because the manifest never leaves estate-controlled hosts. Record that as a stated assumption.
- Splitters: FIXED-{128K..8M}, DYNAMIC-{128K..8M}-BUZHASH, DYNAMIC-{..}-RABINKARP; default `DYNAMIC-4M-BUZHASH`. ALGORITHM, REJECTED for UWCP (same reason as restic CDC).
- **Maintenance safety (the GC race, made numeric)** — `SafetyFull`: `MinContentAgeSubjectToGC 24h`, `RequireTwoGCCycles true`, `MarginBetweenSnapshotGC 4h`, `DropContentFromIndexExtraMargin 1h`, `PackDeleteMinAge 24h` ("Blob GC: Delete unused blobs above this age"), `SessionExpirationAge 96h` ("Drop incomplete session blobs above this age"), `RewriteMinAge 2h`, `MinRewriteToOrphanDeletionDelay 1h`; eventual-consistency settling wait on. `SafetyNone` zeroes all and "the user must ensure that no concurrent operations are happening". A single Maintenance Owner `user@hostname`. Quick maintenance "will never delete any metadata from the repository without ensuring that another copy of the same metadata exists." INVARIANT + ALGORITHM.
- **Kopia #5371 (opened 2026-05-13, fixed by PR #5373, shipped v0.23.1 "fixes a rare race condition which might lead to a data loss"):** epoch-index compaction selected the wrong next epoch; once source index blobs became eligible for deletion, a recompaction produced an incomplete index set that clients could then select — propagating loss. FAILURE PATTERN: **a compaction that deletes its inputs must prove its output is a superset of them first.**

### 3.3 The GC race lesson, stated for UWCP
Deleting "unreferenced" data is only safe against the set of references that exist **now**; a concurrent writer holds references that are not yet published (restic: blobs uploaded before the snapshot/index is written; Kopia: sessions, unflushed indexes). Both systems close it the same two ways: (a) **mutual exclusion with a lock whose loss aborts the writer**, and (b) **age margins** — never delete anything younger than the longest plausible unpublished-write window, and require two GC observations.

UWCP mapping:
- "keep last N receipted capsules per goal" — covered for *receipted* capsules only. Gap: a capsule being captured/uploaded (or queued for the next epoch dispatch) is not yet receipted, so a naive "keep last N receipted" prune deletes the in-flight one or the parts it shares. Rule: retention counts receipts, but deletes only parts that are (1) unreferenced by any of the last N receipts, (2) unreferenced by any queued/running job manifest, (3) older than a margin ≥ max job budget (45 min, §12) + transfer time, and (4) observed unreferenced on two consecutive passes. Falsify: start a capture, run retention with N=0 mid-capture; the capture's parts must survive and its receipt must verify.
- "node stage dirs deleted on harvest by the dispatcher job itself" — this is the node-side GC. Gap: the home's "node-known heads" (§10 incremental bundle) is a belief derived from past harvests; after a stage dir is deleted those heads may no longer exist on the node (F-REAPI-2 shape). Rule: the node answers "have" at dispatch time (FindMissingBlobs), and a missing prerequisite at restore -> fall back to full bundle (§14 "missing branch -> full bundle") rather than NON_EQUIVALENT. Falsify: delete the node's copy of base commit, dispatch incremental; restore must detect `git bundle verify` "Repository lacks these prerequisite commits" and fall back or refuse — never apply partially.
- Harvest deletes the stage dir only after the home has written the receipt AND re-verified every part it references (receipt closure, §1.2). Falsify: kill the home between "download" and "receipt fsync"; the node stage dir must still exist.

## 4. Git as the object model

Sources: git-scm.com docs — git-bundle (page version 2.48.0, 2025-01-10), git-ls-files and hash-function-transition (2.55.0, 2026-06-29), gitattributes, git-config (current); git-lfs `docs/spec.md` on main; public-inbox thread `xmqq4ltpsn42.fsf@gitster.mtv.corp.google.com` (autocrlf + git apply). Git SPDX GPL-2.0-only (latest docs 2.55.0, 2026-06-29); git-lfs SPDX MIT. (git-config wording below is the fetch model's summary, not verbatim; re-check the quotes before citing them anywhere.)

### 4.1 What git already gives
- **Blob/tree ids are content addresses of the CLEAN form.** Checkin runs filter(clean) -> ident -> text(eol); "Line endings are normalized to LF in the index every time the file is checked in". So the blob id is independent of the host's worktree bytes *provided both hosts apply the same conversions*. INVARIANT. This is what makes §14 "CRLF drift -> blob-id identity holds" true — and only under that proviso.
- **`git ls-files -s -z`** gives `<mode> <object> <stage>\t<file>` per entry (stage>0 = unmerged); `--eol` gives `i/<lf|crlf|mixed|none|-text> w/<...> attr/<...>`; `-t` tag `S` marks skip-worktree (sparse); `--format='%(objectmode) %(objectname) %(objectsize) %(path)'` exists. DATA MODEL: the manifest's per-file list is exactly this, captured from the SYNTHETIC index.
- **Modes**: 100644 / 100755 / 120000 (symlink) / 160000 (gitlink = submodule commit). With `core.fileMode=false` (Windows default) and `core.symlinks=false` (Git for Windows default: link checked out as a small file holding the target text) git keeps the mode already recorded in the index instead of reading it from the filesystem. DATA MODEL + TRAP (see 4.3).
- **`git bundle verify`**: "check that a bundle file is valid and will apply cleanly to the current repository ... checks on the bundle format itself as well as checking that the prerequisite commits exist and are fully linked". It does NOT claim to index-pack/fsck the objects; object hashing happens at unbundle/fetch. v3 bundles carry `@object-format`. **So `bundle verify` alone is a structural verify (restic default-check analogue), not a content verify.** Gap in §10. Falsify: flip one byte inside the pack section of a bundle, keep size: run `git bundle verify` (expect it may pass), then `git fetch <bundle>` with `transfer.fsckObjects=true` (expect failure). The capsule's own `{sha256,size}` per part catches this before git is asked.
- **Object format**: SHA-256 repos exist (`extensions.objectFormat=sha256`); SHA-1<->SHA-256 interop (`compatObjectFormat`) is "comprehensive [design] but implementation is incomplete". INVARIANT: capsule records `git_object_format`; restore refuses when node repo format differs. SHA-1 in git is collision-detecting SHA-1DC; acceptable for identity among estate-controlled writers, while transport integrity is the sha256 part digest.

### 4.2 The candidate model, evaluated
Candidate: one canonical-JSON root manifest; every part named by `{sha256,size}`; tracked-tree identity = git tree id of a synthetic index built from base + dirty tracked files (temp `GIT_INDEX_FILE`, `write-tree`); untracked allowlisted files by `{sha256,size}`; verification = recompute.

Verdict: **correct in shape, with five required amendments** (each from a falsification below):
1. **Seed the synthetic index from the base tree (`GIT_INDEX_FILE=tmp git read-tree <base>`), then `git add -- <dirty in-scope paths>` (or `update-index --add --remove`)** — never build it from an empty index. Seeding preserves recorded modes (exec bit, symlink 120000, gitlinks) that NTFS cannot express, and preserves skip-worktree entries that are absent from a sparse worktree. An empty-index build silently drops them.
2. **Two trees, not one:** `index_tree` (from the real index = staged state) and `worktree_tree` (synthetic index = staged + unstaged). This replaces the "staged + unstaged binary diffs" parts as the identity; diffs may stay as a transport optimisation but are no longer what verify compares.
3. **Restore by objects, not by patches:** on the node, `git read-tree <worktree_tree>` into the worktree index + `git checkout-index -a -f` (so the NODE's own smudge/eol apply), then `read-tree <index_tree>` to restore staging. Applying Windows-generated diffs to a node worktree (or node diffs back to a CRLF Windows worktree) is exactly the `git apply` + autocrlf failure (F-GIT-1). The bundle must therefore carry the dirty blobs too: write them with `hash-object -w` during capture and include the synthetic trees as a ref (e.g. `refs/uwcp/<capsule>/worktree`) in the bundle, so `bundle verify`/fetch covers them.
4. **Record the conversion environment as a correctness field (§11 class "correctness")**: `.gitattributes` blob ids (already in the tree), plus host config that affects clean: `core.autocrlf`, `core.eol`, `core.safecrlf`, the set of filter drivers named by attributes in scope and whether each is installed (`git config filter.<d>.clean`), LFS version. Verify on the node recomputes the tree from the restored worktree; any mismatch is attributed to conversion drift, not corruption.
5. **Canonical manifest**: UTF-8, keys sorted, no floats, arrays of entries sorted by UTF-8 path bytes (REAPI rule), paths as git stores them (forward slash, index spelling, not the filesystem's case), `digest_function` and `git_object_format` explicit, and the manifest's own `{sha256,size}` computed over those exact bytes. Capsule id = that digest.

### 4.4 Local code against this model
- `git_state.tree_id()` `work:` hash is over raw worktree bytes of every file under scope including ignored ones (L1/L2 in §0). It is the wrong identity for a portable capsule; the synthetic-index `write-tree` gives the portable one and could become `git:<tree>` even for dirty scopes (then `git:` means "tracked content", and untracked allowlisted content is a separate digest). Keep `work:` only as a host-local label.
- `repo_identity.canonical_repo` is path-based (host-local). Portable repo id = normalised origin URL + root commit id(s) (`git rev-list --max-parents=0 HEAD`), the latter surviving URL changes and forks being distinguishable by base commit.

### 4.5 Git failure-corpus candidate
- **F-GIT-1 — `git apply` fails under `core.autocrlf=true`.** public-inbox git list, thread "core.autocrlf=true causes `git apply` to fail on patch generated with `git diff-index HEAD --patch`" (reply by Junio Hamano, msg-id `xmqq4ltpsn42.fsf@gitster.mtv.corp.google.com`): the worktree file is converted to index form before applying, and `convert_to_git()` consulting current index contents makes the result depend on index state. Abstraction: **a patch is a recipe bound to a byte representation; transfer the objects and let each host render them.** UWCP exposure: direct — §10 ships staged/unstaged diffs across Windows<->Linux.

## MINIMAL CAPSULE OBJECT MODEL (recommended)

```
capsule_id = sha256(manifest_bytes), size = len(manifest_bytes)
manifest (canonical JSON: UTF-8, sorted keys, no floats, LF, arrays sorted by UTF-8 path bytes):
  schema: "uwcp.capsule/1"
  digest_function: "sha256"
  git_object_format: "sha1" | "sha256"
  repo: { origin_normalised, root_commits: [..] }            # portable, not a local path
  base: { commit, tree }
  branch                                                      # label only, never identity
  trees: { index_tree, worktree_tree }                        # git tree ids of real index / synthetic index seeded from base
  scope: { paths: [...], sparse_spec_digest | null }
  untracked: [ { path, sha256, size, mode } ]                 # allowlisted only
  gitlinks: [ { path, commit } ]                              # + nested capsule id if dirty, else refused
  lfs: [ { path, oid_sha256, size } ]
  conversion_env: { autocrlf, eol, safecrlf, filters_in_scope: {name: installed?}, lfs_version, git_version }
  parts: [ { role: bundle|untracked_tar|diff(optional transport), sha256, size, prerequisites: [commit] } ]
  provenance: { host_id, captured_at, epoch_key, run_token }
  ownership: [ ... ]                                          # §10 table
```
Verify = (1) every part `{sha256,size}` matches (size first); (2) `git fetch <bundle>` with `transfer.fsckObjects=true` (not just `bundle verify`); (3) `read-tree worktree_tree` + `checkout-index` on the node; (4) recompute trees from the restored worktree via the same seeded-synthetic-index procedure; (5) recompute untracked digests, gitlink presence, LFS object presence. Outcome: all equal -> EQUIVALENT; trees differ only where `conversion_env` differs and the differing entries are text files -> COMPATIBLE_WITH_DECLARED_DRIFT; any part/object/gitlink/LFS missing or mismatched -> NON_EQUIVALENT with the named digests/paths; a check that could not run (filter driver absent, git error) -> UNKNOWN. Retention: keep parts referenced by the last N receipts ∪ queued/running manifests; delete others only after age > max epoch budget + transfer margin AND seen unreferenced on two passes.

## DISPOSITIONS

- **bazelbuild/remote-apis** (Apache-2.0; tag v2.12.0 / v20250211, main `adbf4a2` 2026-09-22): **ADAPT DATA MODEL.** Take Digest{hash,size}, canonical sorted form, Action->epoch key, ActionResult+ExecutedActionMetadata->receipt, FindMissingBlobs, "referenced blobs must exist" and "non-OK never cached", ExecutionStage. Cost: schema work only, no dependency. Benefit: a vetted vocabulary whose failure modes (items 1-3) are already documented.
- **bazelbuild/bazel** (Apache-2.0, 9.2.0 2026-07-13): **REFERENCE ONLY** (failure corpus source).
- **dagger/dagger** (Apache-2.0, v0.21.9 2026-08-26): **REFERENCE ONLY.** Absorb recipe-vs-content digest naming, explicit allowlist before upload, OTel attribute conventions. Rejected as dependency: BuildKit daemon + its own cache/GC per node, wrong unit of work.
- **restic/restic** (BSD-2-Clause, v0.19.1 2026-07-05): **ABSORB CONCEPTS.** Lock-loss-aborts-writer, "remove from index before delete", structural vs `--read-data` vs subset verify. Reject CDC and its mtime-bearing tree identity. No dependency.
- **kopia/kopia** (Apache-2.0, v0.23.1 2026-06-16, master `1d4d45a` 2026-09-25): **ABSORB CONCEPTS.** Numeric safety margins (24 h min age, two GC cycles, 96 h session expiry, single maintenance owner) scaled to UWCP (margin ≥ max epoch budget + transfer), and the compaction lesson from #5371. Reject keyed IDs and CDC for the capsule. No dependency.
- **git** (GPL-2.0-only, docs 2.55.0 2026-06-29) + **git-lfs** (MIT): **ADOPT as the object model** (already a dependency). Cost: a synthetic-index capture (~a dozen git plumbing calls) and restore-by-objects in place of apply-by-patch. Benefit: CRLF/mode/symlink/sparse identity handled by git's clean form instead of raw bytes. Required: record object format, conversion environment and LFS; use `fetch` with `fsckObjects` for content verification, not `bundle verify` alone.
