# Prompt para Claude Code — integrar el ZIP en CDIO / Claude Power Pack

Actúa como el ingeniero principal de integración del Chief Design Intelligence Officer dentro de Claude Power Pack. He adjuntado el paquete CDIO_Elite_Web_Experience_Agent_Pack_v1.0.0.zip, que contiene nueve agentes especialistas, prompts de sistema y rol, definiciones opcionales de subagentes Claude Code, protocolos de colaboración y pruebas de aceptación.

Tu misión es integrar semánticamente todas las capacidades útiles del paquete en el CDIO REAL que esté presente en este repositorio, de manera autónoma, sólida, sin duplicar autoridades y sin inventar ninguna interfaz técnica.

Primero realiza un Reality Scan exhaustivo del repositorio. Localiza CDIO Core, reviewer, Standards Librarian, scorer, design_gate, design_index, CCF, CDICF, DESIGN.md, Knowledge Vault, UKDL, Production Reality Gate, Baseline Ratchet, capacidades de navegador, frameworks de componentes, agentes y rutas existentes. Verifica implementaciones, propietarios, versiones y contratos actuales. No supongas que existen en rutas fijas y no cambies lo que ya funciona.

Para cada uno de los nueve roles compara capacidades con lo presente y elige explícitamente REUSE, EXTEND, MERGE, CONNECT o BUILD. No crees nueve duplicados si roles existentes cubren esas responsabilidades: absorbe criterios nuevos en los agentes canónicos y crea solamente las unidades que aporten capacidad real. El CDIO existente debe seguir siendo autoridad de revisión y el sistema de ejecución existente debe seguir construyendo; jamás montes un segundo design system, una nueva fuente competidora de identidad o un runtime de orquestación paralelo. DESIGN.md mantiene la autoridad que ya tenga.

Elige el modo de trabajo por ROI: EXECUTION si los cambios están bien delimitados, PLAN si hay dependencias, ULTRA-PLAN si se requiere una integración transversal compleja. Para PLAN/ULTRA-PLAN, presenta el plan completo directamente en el chat para su aprobación conforme a los mecanismos del entorno; respáldalo en el plan-file si así lo exige el repositorio, sin sustituir el plan inline. Respeta permisos existentes y no despliegues a producción ni realices actos externos irreversibles sin autorización.

Asegura que, al comenzar cualquier misión de creación, auditoría o rediseño web, CDIO seleccione automáticamente solo los especialistas necesarios, con contratos de entrada/salida, ownership, límites de acceso, revisión adversarial y criterios de completitud. Permite investigación paralela con Agents/Subagents/Agent Teams cuando resulte más eficiente y seguro; evita coste y conflictos injustificados.

Integra un workflow que comprenda: intención del producto, descubrimiento de evidencia, análisis interdisciplinar, alternativas de arquitectura, decisión y diseño canónicos, plan inline cuando proceda, implementación reutilizando capabilities existentes, pruebas en navegador real, revisión independiente CDIO, documentación de defectos y promoción al baseline solo con pruebas fresh-agent. Cubre móvil, escritorio, accesibilidad, rendimiento, datos comerciales verificados, navegación, formularios, estados, microinteracciones, reduced motion y conversión real.

Exige evidencia reproducible antes de aceptar cualquier gate. No inventes datos, métricas, capturas, decisiones del propietario, resultados de tests o estructuras del repositorio. Todo bug descubierto o corregido debe documentarse en el Knowledge Vault y su patrón universal en UKDL mediante los mecanismos verificados. Promociona reglas útiles y comprobadas al Baseline Ratchet después de tests adecuados, sin introducir reglas universales basadas en una sola preferencia.

Trabaja incrementalmente con microcommits, pruebas y reversibilidad. La definición de terminado debe impedir botones vacíos, placeholders en producción, datos falsos, regresiones visuales, problemas graves responsive y acciones imposibles de completar. No marques integrado un rol si no puedes demostrar delegación real o alcance equivalente en el agente existente. Valida instalación y compatibilidad con misiones fresh-agent, incluida una misión de restaurante como MYTILUS y otra web genérica de sector distinto.

Finaliza con: mapa exacto de integraciones reales, clasificación REUSE/EXTEND/MERGE/CONNECT/BUILD por rol, rutas comprobadas, cambios y microcommits, pruebas ejecutadas y resultados, defectos y limitaciones pendientes, contratos de activación autónoma, veredicto CDIO canónico cuando esté disponible, evidencia de no-regresión y próximo paso claro. Si existe un bloqueo genuino, conserva el resto del progreso y genera un handoff inequívoco; no declares finalizado lo que no se pudo comprobar.
