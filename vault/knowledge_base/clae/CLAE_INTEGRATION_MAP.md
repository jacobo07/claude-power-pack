# CLAE — Integration Map

> **What this file is.** Part XXVI §5 defines the twelve companion artifacts as *"extracts for retrieval convenience"* — the schemas, consolidations and measured counts live in the Parts. This file locates entries; it does not restate, resolve or extend them.
> **Reading rule.** Every row cites the Part that seeded it. Where a row's source is ambiguous, the ambiguity is transcribed rather than resolved.

## 2. The integration map

Every owner named in the charter's non-scope table, plus those identified during construction. The
column that matters is the third: what CLAE does **not** touch.

| Canonical owner | CLAE's relationship | Untouched |
|---|---|---|

The pattern is deliberate and worth stating: **CLAE adds fields, criteria and vocabulary to existing
surfaces, and replaces none of them.** Every proposal in the family is additive. That was the
constraint Phase 0 imposed when it measured that most of what the corpus proposed was already owned
here, and the map is the evidence that the constraint held.

## 3. Consumes, produces, registers

**Consumes:** the reachability audit's discovery discipline · the artifact done gate's contracts ·
the design scorer as the proven graded instance · the recurring-error log's identity scheme · the
findings transport · the hard-rule archive's provenance model.

**Produces:** the residual ledger with identity, mode and coverage · floor derivations with threshold
placement · oracle boundary declarations · Phase Zero verdicts with measurement-debt registers ·
deviation records with measured loss · the four-point gate set with label propagation · durable
probes from incidents.

**Registers into:** the rule archive (118 process rules, labelled deductive) · the trap registry (99
entries) · the eval set · the compendium integration spine.

## 4. What CLAE deliberately did not build

Recorded because a family's restraint is as much a result as its output, and because Phase 0's
central finding was that the corpus proposed a great deal this stack already had.

Not built: a rule placement compiler; a second semantic graph; a succession mechanism; a
just-in-time loader; an epistemic ladder; a side-effect detector; an egress gateway; a dashboard;
a decompiler; a resource-residency runtime. Each has a canonical owner, was verified during the
Phase 0 audit, and is referenced rather than duplicated.
