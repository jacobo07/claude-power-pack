# S3 displacement audit (phase 4)

G1 BLOCK  V-SPV2-NO-WRITE-SQL (test_spawn_policy_v2.py:177-179) regex-scans the RAW source of estate_shadow.py, comments and docstrings included, case-insensitive: `\b(INSERT|UPDATE|DELETE|REPLACE INTO|ALTER|DROP|CREATE)\b\s`. Any new docstring saying "update ", "create ", "drop " fails the gate. Fix: write the prose without those words, or put displacement in a new module (tools/estate_displacement.py) and add a same-regex scan of it in test_displacement.py (the existing gate would no longer cover it).
G2 BLOCK  RAN_LATER_EQUIVALENT drops the plan's "same root" condition (s14 plan line 40-41). Without it a same-hash spawn in another session/root hours later counts as "the work ran later". Require same resolved root (fl.root_resolver on spawns.file / prompt_id) AND a horizon (e.g. root lifetime or 24h). Otherwise it inflates displacement and shrinks the saving claim spuriously.
G3 FIX    REUSABLE_RESULT_EXISTED: in Python `None <= t` raises TypeError; result_ts is NULL for spawns with no recorded result (usage_index.py:83, only set at :192). Guard result_ts IS NOT NULL and require is_error == 0 (not "falsy": NULL must mean unknown). Also usage_index._spawn_results (:187-195) takes the FIRST tool_result for the id; for a background/async agent that can be a "launched" ack, not the result -> false REUSABLE. Inspect result_head or accept the hole and say so. Self-match: exclude other == tuid, and use (ts, tuid) ordering so equal-ts parallel duplicates do not each count the other as "later" or "earlier".
G4 FIX    Signature: replays' receipts carry no input_hash/ts (subject has tool_use_id only; ts only as ISO in features.as_of). Take the `sp` list from spawns_in (has ts, input_hash, subtree_calls, subtree_cache_read, prompt) plus the existing Equivalents instance instead of rebuilding from con; displacement(con, receipts, sp, eq=None).
G5 FIX    "Upper bound" is not one: spawns_in (estate_shadow.py:85-87) sums calls of the child's OWN file only (grandchildren live in their own subagent files), and missing transcripts yield None counted as 0 (`or 0`, :270 and :186). Report no_transcript and nested-excluded counts and label the figure "child-file observed cost, excludes grandchildren and missing transcripts", or the interval's upper end can be understated.
G6 FIX    Class semantics are mixed in one interval. REUSABLE/EQUIVALENT_ACTIVE are potential-saving candidates (work could have been reused); RAN_LATER/OVERLAP are displacement (saving ~0). Report per class and state the headline as [0, UB of the potential-saving classes + UNKNOWN]; never sum displaced classes into the upper end as if equally possibly saved. interval lower 0 is a constant: a test of it is vacuous (keep it as a documentation pin only).
G7 FIX    Hindsight leakage: receipts hold `features` by reference (spawn_receipt, scheduler.py:438-443), so displacement must never write into feats/receipts, and must run after `reconstructed` and after `receipts` is final. Attach as the last key of result. Add a static test that scheduler.py and the receipt builder do not import the displacement function, plus byte-identity of receipts with displacement monkeypatched out vs in (json.dumps sort_keys). Recommendation (`recommend`) must not read it.
G8 FIX    PARENT_OVERLAP: 0.5 threshold is not defensible. Real data: max 0.111, 11 at 0 -> the class can never fire on the only real evidence, so it is untested on reality and unfalsifiable. Report the raw overlap only (no class, no precedence slot); if a class is kept, require min child tool inputs (>=5) so 1/1 is not 100%, and name the threshold as unvalidated.
G9 FIX    Overlap is directionally weak even when measured: parent re-issuing a Read after the child returned means redundancy/re-verification, not that the parent would have absorbed a deferred child's work. Window "after t" includes parallel calls emitted in the same assistant message as the Agent call (ts == t) and the child's running time; define the window as (result_ts, +bound]. Exact-string matching (Windows path case/slashes, Bash text) under-measures (conservative, fine) but state it. spawns.file IS the transcript holding the tool_use (usage_index.py:429, path), so the parent is correct; resumed/compacted sessions continue in other files -> under-measure, NOTE. Child transcript = subagents.file where subagents.tool_use_id = spawn id; absent row -> None.
G10 FIX   Cost/RAM: max_overlap counts spawns, not bytes. Parent session transcripts are large; stream line by line with a substring pre-filter, cache per parent file (many spawns share one), keep only hashed (ts, input) tuples, and add a byte budget; spend the cap only on spawns not already classified by classes 1-3 (they do not need overlap). Python open() on Windows shares read/write, so no EBUSY (the .NET ReadLines hazard in memory does not apply).
G11 FIX   PRG test "reproduces 1/19 on the real index": the index is live, results/hashes backfill and window data drift; the test is environment-bound. Make it an explicit SKIP/INCONCLUSIVE (never PASS, per the inconclusive-counted-as-pass rule) when the index is absent, and assert invariants (class counts sum to non-ALLOW count; REUSABLE+ACTIVE == 0 only as a reported fact) rather than exact numbers, or snapshot the index bytes by hash.
