# ccp-s16 C3 phase-4 audit (rollover replay)
G1 FIX (Q1, price book): rollover.py:169-180 `price_ratio` reads `books[-1]`, the NEWEST dated book, for every boundary; a 2026-09 boundary is priced with a later book. Only write/read ratio matters, so impact is small, but pick the newest book dated <= boundary ts (session_autopsy._price_books has dates) or label the ratio TODAY_BOOK on every row.
G2 FIX (Q1, capsule median): median bootstrap_chars over ALL shadow rows includes rows written after the boundary (rollover.py:715 writes them at seal time). Filter rows by ts <= boundary ts; with <5 rows use a labelled constant, never a silent later value.
G3 FIX (Q1, window): `used_pct = resident/1e6*100` hardcodes a 1M window. decide's pressure branch (rollover.py:525) returns WOULD_ROLLOVER at 70% whatever the horizon. Take the window from the model of calls[i-1], or pass used_pct=None and say so. A 200k-window session would otherwise never hit the branch.
G4 BLOCK (Q1/Q4, corpus censoring): corpus = ledger-named sessions, i.e. sessions that were ROLLED OVER, CLEARED or hit the wall. Their `total_calls - i` is censored by the very policy under test (they ended because context was spent, not because work finished), so the prior is biased low and circular. Either add same-store transcripts without a rollover/clear row as the main corpus, or report the censored fraction and refuse a verdict above a threshold.
G5 FIX (Q1, corpus eligibility): "last call ended before boundary ts" needs one clock. Compare row `timestamp` parsed UTC on both sides; today's gsd_epoch._ts (gsd_epoch.py:103) and rollover._rows are separate parsers. Predecessor/successor of the SAME capsule chain (ledger successor_claimed) must be excluded from the corpus of their own root, or the prior sees the root's own future.
G6 FIX (Q3, usage shape): decide needs {"state":"OK","floor","resident","model"} (rollover.py:513-517,165). Build it exactly like usage_facts, with model = calls[i-1].model, NOT calls[-1] (the last call of the whole session is a future model). `boundary=True` must be passed explicitly; at_boundary(repo,start_head) cannot be called from a transcript, so say the boundary is commit-tool-use based, not commit-landed.
G7 FIX (Q3, boundary detection): is_commit_command (rollover_replay.py:46) matches `git commit --dry-run`, `--amend`, and any Bash text, and the tool_result is never checked, so a hook-rejected commit counts. Require the matching tool_result not is_error and drop --dry-run. Also `_mutating_message_ids` (line 70) bundles Write/Edit with commit; a commit-only variant is needed. Do not copy the loop; parametrise it.
G8 FIX (Q2, algebra): n*_adj = n* + R*fresh/growth is correct (extra cost R*fresh*read, divided by growth*read; read cancels) but do not recompute it. Algebraically n*_adj <= h  <=>  n* <= h - R*fresh/growth, so call decide(horizon = h - R*F/G) with F=bootstrap_est+floor and G=growth_above_fresh from decide's own output. That keeps the pressure and MIN_GROWTH_TOKENS(150k, line 46) gates single-sourced; a hand-rolled n*_adj forks the policy. Negative horizon is simply CONTINUE.
G9 NOTE (Q2): R = calls_to_first_mutation is held at constant `fresh` context, but those calls carry the successor's growing ctx (replay measures carried_before_first_mutation); R*fresh understates cost. It is also an upper bound including real work. Say both; consider using carried_before_first_mutation p50 directly.
G10 FIX (hindsight evaluation): exposure interval omits the one-time write premium fresh*(write-read)/read (the n* numerator), so it is not comparable to the break-even the verdict used. Add it to both ends. growth_T is frozen at T although growth keeps rising: the saving is a lower bound; label it. actual_remaining includes trailing non-work calls after the last commit; report from the last commit too.
G11 BLOCK (controls): two short sessions -> CONTINUE passes trivially through `growth < 150,000` and proves nothing. Golden root 8b2c7516 may never reach floor(140,072)+boot+150k; if max(ctx) is below that, all variants are CONTINUE and the instrument cannot return WOULD_ROLLOVER at all. Require a positive control (synthetic ctx series that crosses it, and pressure at 70%) and assert the golden root's max growth first.
G12 FIX (Q4, quantiles): p25..p75 of >=5 values is a noisy order statistic; use _dist's `pick` (line 98) to avoid a second quantile convention. Simpler and more honest: report empirical survival S = share of corpus values >= n*_adj (one number, no arbitrary quantile, no ternary UNKNOWN glue); verdict WOULD if S >= 0.75, CONTINUE if S <= 0.25, else INSUFFICIENT_EVIDENCE. Equivalent to p25..p75 but also shows how far.
