# Trap awaiting absorption

**`T-SOURCE-INVENTORY-IS-A-HYPOTHESIS-001`** — An external proposal's inventory of
*this* estate is a hypothesis about the estate, and it is wrong in one direction:
toward absence. *Observed:* a 6,395-line corpus proposal opened with "I have directly
inspected the roughly 2,200 surfaces of the attached repository" and produced a system
map that was accurate on 9 of 10 named surfaces — and blind to four sealed families it
never enumerated (`crawl_os`, 5 datasets SEALED; DAIF-03, 20 Parts; CLAE, 26 Parts;
ACIS). Every capability it proposed to build in those four territories was justified by
their absence from *its own list*. It also routed causal output to **KADOS**, a system
with exactly one mention in this repository, inside a plan file — CLASE 1, a plan
assuming an API that does not exist.

*Mechanism:* a source cannot enumerate what it did not open, and an inventory that
omits a family reads that family's territory as vacant. This is
`PR-COVERAGE-BY-CONSTRUCTION-001` arriving from outside instead of from a hand-written
registry — same defect, different author.

*Rules:* (1) before acting on any external analysis of this estate, re-derive the
denominator by enumerating the filesystem, never by reading the analysis's own list;
(2) probe every named surface with `Test-Path` before designing against it — a bridge
to a non-existent system is load-bearing until someone checks; (3) a source's *founding
claim* deserves the same treatment as its details — the claim "PP lacks a unified owner
for X" was correct here, and the claim "PP therefore lacks the organs of X" was false,
and only a sweep separates the two.
