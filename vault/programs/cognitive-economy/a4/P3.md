## The three clauses (manifest `man.get("ci")`, a dict; any key may be absent -> that clause is not emitted)
1. `meta_work` (D-22). Key `meta_work_max` (float 0..1). share = coordinator_spend / (coordinator_spend + sum(attempt_spends)).
   Any operand not an int -> ("FAIL", "meta-work unmeasured"). share <= max -> PASS, else FAIL.
   Evidence string: `share=<0.xxx> max=<m> coordinator=<n> workers=<n>`.
2. `token_incident` (D-24). Key `incident_ratio` (float > 0). A step is an outlier when its int `spend` > ratio x its int `cap`.
   An outlier is green only if `ci.get("incidents", {})[step]` names a non-empty file under root (the incident record).
   No outliers -> PASS "0 outliers". Any outlier without a record -> FAIL "unrecorded: <steps>". A step lacking int spend or
   cap -> FAIL "unmeasured: <steps>" (absent is never zero).
3. `hot_token_delta` (D-28). Keys `hot_base` (commit), `hot_files` (list of repo-relative paths), `hot_delta_max` (int bytes,
   default 0). delta = sum(len(bytes) of each file in root now) - sum(len(`git -C root show <hot_base>:<f>`)).
   A file missing at base counts 0; a git error or missing file now -> FAIL "unmeasured: <f>". delta <= max -> PASS.
   Evidence: `delta=<n> max=<m> base=<sha7>`.
Insert them after the `spend` clause and before the extra-clauses loop, so CLAUSE order is receipts, violations, spend,
meta_work, token_incident, hot_token_delta, extras.
