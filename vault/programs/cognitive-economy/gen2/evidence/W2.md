## W2b. E1 (`m-f011d7fdebc9`) cannot relay: root cause

Sweep at 10:04:18Z and 10:09:38Z:
`action=replace reason="owner dead: host lists session done" stop="pid 4165820 still alive after 90 s; not terminated: argv is not this worker"`

- owner record: `session_id 68d51544-...`, `pid 4165820`
- `ps -p 4165820`: `claude bg-spare --bg-spare /tmp/cc-daemon-1000/38442ce8/spare/b28b1b24.claim.sock`, alive 1h45m

Cause: on GEX44 the Claude daemon runs background sessions in pooled `bg-spare` processes. The host-reported
pid is that pooled process. When the session ends (host `done`), the process stays alive as a spare. Its argv
never carries `--session-id <sid>`. `tools/gsd_mission.py` stop path (around the "argv is not this worker"
return, ~line 1331 at HEAD `866f1ecc`) therefore refuses to kill it, which is correct because it is the
daemon's, and then also refuses to relay. Every 5-minute pass repeats this, so the mission makes no progress.

Proposed semantics for the owner (not implemented here):
when the host says `stopped|done|exited|failed` AND the pid's argv identifies a daemon pooled process
(`bg-spare` / `bg-pty-host`) that does not carry this worker's session id, the worker has been released.
Return released ("host done; pid is a daemon spare, not ours"), never kill it. Regression test: fake host row
`done`, `pid_alive=True`, cmdline `claude bg-spare --bg-spare ...` -> released, killer not called. Plus a
control: cmdline with `--session-id <sid>` -> killed as today; unreadable argv -> refusal as today.
G23 legacy characterization must stay green.

Why not fixed here: `tools/gsd_mission.py` was dirty in the shared tree from the live capsule-v2 pane
(commits 22b55d3b, bc4df9dd, 866f1ecc on 10-05), and GEX44 runs its own clone at stale `339ccaa9`, so a fix
also needs a deploy to that clone. Handed to that owner: `../handoffs/W2-gsd-mission-bg-spare.md`.
