# T2-0.5 item j: can session_budget_guard cap a subagent? (W-a2, marker T205-WA2-M3)

ANSWER: NO, not without capping its parent. Guard cannot cap a subagent without capping its parent.

Evidence
- hooks/session_budget_guard.js decide(): keys ONLY on event.session_id (budget file session-budget-<sid>.json) and reads event.transcript_path for the spend. It has no agent_id handling.
- A subagent transcript (agent-ac18dc84afc8abaa0.jsonl) records sessionId = a5fafaa2-6f7d-4ce6-a146-a8104c44edf9, the PARENT id, on every line (isSidechain true, agentId distinct). The session id available to key on is the parent's.
- Probe (negative for the distinct-id hypothesis): declared a budget for the subagent's own agentId (ac18dc84afc8abaa0, stop 2,000,000, --since now), then made gated PowerShell calls. No session-budget-ac18dc84afc8abaa0.state.json appeared (the guard writes it on every judged call), so the guard never saw that id. The probe file was deleted afterwards.
- A budget declared for the parent id would meter the parent's ~23M transcript and lock the parent out. NOT done (forbidden).
- Limit: I could not capture the raw hook event (hook logs omit session_id), so "guard fires with sid=parent" is inferred from the transcript sessionId plus the absent agent-id state file, not observed directly.

Controls
- Positive: python tools/test_session_budget_guard.py -> SBG_PASS=17/17 (over stop -> deny; V-SBG-E2E live dispatcher -> deny) on scratch ids in the tool's own test path; no self-block.
- Negative: the agentId probe above (no deny, no state file); V-SBG-KILL and V-SBG-EXEMPT in the same suite.

Consequence: subagent spend is capped only by self-metering (gen3_t2/meter.py every 3 calls). Fixed floor measured ~120k processed per call, so a 2.0M cap is about 16 calls.
