## Design (implement; change only with a reason written in the receipt)
- A workspace (normalised cwd root) holds at most one lease holder: record {workspace, goal, lease, gen, holder_sid, ts} in a
  new append-only journal `workspace.journal.jsonl` under the goal dir, written by a new GoalLedger-adjacent module
  modules/provider_routing/workspace_registry.py (same Exclusive lock + seq + fsync idiom as ledger.py).
- `claim(workspace, goal, lease, expect_gen)` is a CAS on generation: succeeds only if expect_gen == current gen; gen+1, holder
  replaced. A claim by a stale gen is refused naming the winner. Idempotent by (workspace, goal, lease, gen).
- Binding precedence (resolve_binding): explicit registry holder > goal roots from the index > none. A cwd entry into a goal
  worktree is OBSERVE only: it never binds, never claims, never settles (that was the 32.8M mis-attribution, memory
  feedback_coordinator_set_location_binds_goal).
- Zombie fencing: a settle/renew carrying a gen lower than the workspace's current gen is refused and journalled as fenced; the
  fenced sid's spend is still booked as spend (never dropped), only its lease authority is revoked.
- Closed lease holder: if the registry names a lease that lineage() reports closed, the guard must treat the holder as FENCED,
  not as UNKNOWN-free.
