# 05-03: close the A->B->A hole in evidence_bundle (R05)

## Design
A content hash cannot see "A, then B, then A". Two layers, both content-or-stat based, no new store:
1. **Snapshot**: `ticket()` reads each artifact ONCE, hashes that buffer and writes the same bytes read-only under
   `_logs/evidence/<plan>/<task>/snapshot/<posix path>`. A reply that echoes `snapshot_line(nonce)` was written
   for the snapshot; the reviewer read bytes no live writer can change. `write_review` re-hashes the snapshot
   files against the ticket; a mismatch fails the review (snapshot tampered).
2. **Journal**: the ticket also stores per artifact `{mtime_ns, size, ino}` (+ `ctime_ns` off Windows). A reply with
   no snapshot echo is a LIVE read: `write_review` compares the journal with the files now, and any difference
   (including a rewrite back to the same bytes) fails with the path and `bytes were rewritten between the ticket
   and the reply`. A ticket written before this change has no journal: a live read of it fails closed.
`ticket(...)` keeps returning `(path, nonce)` (the existing suite unpacks two values); the CLI prints both lines.
Residual, recorded not hidden: on Windows a writer that deliberately restores `mtime_ns` and the inode defeats the
journal for a live read; the snapshot path is the proof.
