<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git stderr -> card ledger | stderr can carry absolute paths, remote URLs, user names |
| test suites -> live ledger | a test that starts the card without a private state dir writes into the Owner's live ledger |
| gate env -> git | the gate sets GIT_TEST_ASSUME_DIFFERENT_OWNER / GIT_CEILING_DIRECTORIES for child git only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06 | Information disclosure | ledger row on git failure | medium | mitigate | Only the `git_error` class enum is stored, never raw stderr (HR-SECRET-002). Acceptance greps that no `stderr:` field exists in the card. |
| T-01-07 | Tampering | live doctrine-card ledger | high | mitigate | The capsule test gets a private `DOCTRINE_CARDS_STATE_DIR`. V-SCA-STATE-DIR-SWEEP with a floor plus V-SCA-STATE-DIR-DRILL make a regression go red. |
| T-01-08 | Elevation of privilege | empty-tree fallback | low | accept | It changes only what the card diffs against (a read-only `git diff` / `hash-object --stdin` that writes no object without `-w`). The card remains deny-once and never an authority. |
| T-01-09 | Denial of service | extra git spawns | low | mitigate | The fallback runs only on the unborn_head failure path. Each spawn is bounded by GIT_TIMEOUT_MS and the hook's dispatcher timeout. |
</threat_model>
