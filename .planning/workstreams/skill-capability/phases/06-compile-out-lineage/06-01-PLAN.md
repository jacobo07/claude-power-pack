<objective>
Implement D-01 and D-02 for pillar G (SC-G): every compiled-out card names the skill, source path, source digest and
source commit it was compiled from, and one tool judges that lineage against committed blobs, reusing phase 4's
card-vs-source functions instead of building a second comparator. Keep pillar H's record and evidence current after
the card edit (the edit changes card bytes that H pins).

Purpose: the frozen G rule is "a compiled-out card names the skill and commit it was compiled from, and a gate fails
when the source skill changes without the card being re-derived". H's record alone does not satisfy it: H can be
re-recorded without anybody re-reading the skill. G puts the lineage inside the card, so re-recording H does not clear
a source change; only rewriting the trailer does (the drill for this is in 06-02).
Output: `tools/card_lineage.py`, two trailers, the re-derived H record and H render, two moved state.H pins.
