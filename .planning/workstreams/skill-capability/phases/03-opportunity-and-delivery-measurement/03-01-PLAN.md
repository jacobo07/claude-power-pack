<objective>
Implement D-01 and D-03 for pillar C (SC-C). Build one gate that computes opportunity, delivery, recall and
precision from card rows plus transcripts over a named window. Prove it on a committed known-answer fixture
window F. Extend the frozen owner `tools/skill_invocations.py` with row-time bounds, because both the per-judgement
join and a pinned live window (plan 03-02) need them. Drive the gate red with mutants and with one subprocess run.

Purpose: the frozen C rule requires one gate that reports n for each rate and never estimates from n < 5. A gate
that can only print green proves nothing, so every refusal (mentions, invocations after the judgement, a missing
transcript read as "not delivered", double-counted re-issues, ratios at small n) has a mutant that goes red.
Output: the owner extension and its test clause, the gate, the fixture, and the first render of `C-delivery.md`.

Host plane: everything in this plan is host-independent (fixture only, no ~/.claude read in the gate's default mode).
Windows L (laptop pack) and G (gex44 transcripts) are plan 03-02.
</objective>
