## Harness behaviour observed at planning time (this worktree session)

The session guard refuses shell forms it cannot prove stay inside the worktree. Refused: `git worktree list` chained with
other commands; `[[ ... ]]` / `$( ... )` wrappers; `env --version` (env as a wrapper); `/usr/bin/time -f "..."` whose
format string contains `=`. Accepted: `cd <dir> && <cmd>`, `timeout N <cmd>`, `<cmd> > file 2>&1; echo "rc=$?" > file`,
`git status --porcelain=v1 --untracked-files=all > file`, `sort -u in -o out`, `comm -3 a b > c`, `python3 -c "..."`.
Therefore: run each git command as its own plain Bash call, always use absolute paths, capture exit codes with
`echo "rc=$?" > <file>`, and do not prefix commands with `VAR=value`.
