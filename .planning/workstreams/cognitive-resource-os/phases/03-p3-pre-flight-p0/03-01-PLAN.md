## Excerpt protocol (Tasks 1-2)

- Grep the RESOLVED binary path recorded in section 0 (never the symlink), so the evidence is pinned to binary_sha256.
- Each excerpt Xnn is numbered from X01, and no number is ever reused. Append to P/raw/static-excerpts.txt a header
  line `### Xnn <what it shows>`, then a line `cmd: <the exact grep pipeline>`, then the output with every line
  prefixed `> `. The form is: `timeout 120 grep -a -o -E '<regex>' <resolved binary> | head -n 3 | cut -c1-600 | sed
  's/^/> /' >> <P>/raw/static-excerpts.txt`. A regex anchors on a string literal and puts its context AFTER the
  literal (`'<literal>.{0,400}'`). Leading context is capped at `.{0,200}` and used only when unavoidable, because it
  is slow.
- Excerpts are evidence, not bulk vendor code: at most 3 lines of 600 chars each.
- Identifier-hop rule. A link that passes through a minified identifier counts toward E2 only when that identifier's
  definition occurs exactly once in the binary. Check with `timeout 120 grep -a -o -F 'function <id>(' <resolved
  binary> | wc -l`, which must print 1, and record the count in the citing block's `evidence:` line. Otherwise the
  link is unestablished.
- E2 for a rules effect needs at least one excerpt that shows the rule-file path itself (a literal such as `rulesDir`,
  `"rules"` or `.claude/rules`) being gated or filtered by the mechanism.
- Redaction (HR-SECRET-002): excerpts are never rewritten. The checks assert that
  modules.secret_firewall.redactor.redact leaves every committed file unchanged. If it would change one, replace that
  excerpt with a narrower window.

## Candidate block format (EVIDENCE section 2b; one block per candidate)

A header line `### Cnn <short name>`, followed by exactly these twelve `- key: value` lines, each on ONE line:
- `mechanism:` the exact invocation or setup form arm B would use. It is quoted verbatim into p0_verdict on a PASS,
  so it must name the concrete flag, file or variable and its value (for a settings JSON, list the three R1 rule files).
- `source:` where it was discovered, for example `help:--settings (raw/claude-help.txt)` or `binary settings key
  claudeMdExcludes (raw/discovered-surface.txt S)`.
- `changes:` what it changes in the session, per the installed version's text or trace.
- `touches_on_disk:` which files it reads, writes, creates or relocates, or `UNKNOWN (<why>)`. Never guessed.
- `rules_effect:` one of
  - EXCLUDES_R1_ONLY: drops exactly the three R1 files; every other memory file loads as in arm A.
  - EXCLUDES_MORE_THAN_R1: drops R1 plus other prefix parts, such as all user memory, CLAUDE.md, user settings,
    skills or hooks.
  - SETTINGS_ONLY: affects settings files, and the text/trace shows no effect on rule files.
  - NO_EFFECT_ON_RULES: adds or changes something unrelated to memory loading.
  - CANNOT_ESTABLISH_WITHOUT_MODEL_CALL: neither the installed version's text nor a traceable code path decides the
    effect on rule files.
- `evidence_tier:` one of
  - E0: no evidence.
  - E1: the installed version's own user-facing text states the effect. This is help output or a settings-schema
    `.describe(` string.
  - E2: code excerpts establish the path.
  - E1+E2: both.
- `evidence:` help quotes of up to 200 chars and/or X-ids, plus identifier-hop counts.
- `credential:` one of
  - NONE_NEEDED.
  - NEEDS_COPY: the credential must be made present somewhere else. That covers a copy, a symlink (a token refresh by
    the arm would write the Owner's live credential through it), or the token value exported into an environment
    variable.
  - NEEDS_API_KEY.
  - NEEDS_NEW_CREDENTIAL: setup-token or a login produces a new credential, which needs the Owner at a browser
    mid-run.
  - CANNOT_ESTABLISH.
- `global_edit:` `NONE`, or `EDITS (<path>)` for any write, move or rename under ~/.claude or of ~/.claude.json.
- `auth_path:` one of
  - OAUTH_UNCHANGED: authenticates with the existing subscription credential exactly as arm A does.
  - API_KEY_ONLY: forces API-key / apiKeyHelper auth, which is paid spend and forbidden in this workstream.
  - CANNOT_ESTABLISH.
- `other_prefix_changes:` `NONE`, or what else would differ from arm A: tools, permissions, hooks, settings, system
  prompt text, the environment block, the arm worktree's git status.
- `transcripts_visible:` YES (the session's transcripts still land under /home/kobii/.claude/projects, where
  tools/tis_observed.py, the protocol's instrument, reads them), NO, or CANNOT_ESTABLISH.
