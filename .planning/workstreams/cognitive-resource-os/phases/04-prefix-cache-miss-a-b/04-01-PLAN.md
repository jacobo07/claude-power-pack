## Pre-registered design (copied into EVIDENCE section 1 by Task 2; ab_runner.py implements exactly this)

- Hypothesis, operational form (H). With the default MCP configuration, a second identical back-to-back `claude -p`
  session reuses materially less of its startup prefix from cache than the same pair with MCP stripped. In addition,
  Arm A's MCP surface (its init tool-name set or its MCP server status map) differs between its two sessions.
- Arms:
  - Both arms: prompt `Reply with the single word OK.`, `--model haiku`, `--output-format stream-json --verbose`, and a
    fresh `--session-id` UUID per run.
  - Arm A adds nothing more: default MCP, user settings, plugins and hooks exactly as configured.
  - Arm B appends `--strict-mcp-config --mcp-config S/empty-mcp.json`, where the file holds `{"mcpServers":{}}`.
  - argv order is [exe, -p, PROMPT, --model, haiku, --session-id, SID, --output-format, stream-json, --verbose], plus
    B's three trailing elements. The prompt sits right after -p, and the only variadic option is last with nothing
    after it (W8).
  - The flag that disables session persistence is never used.
- Model: haiku, the lowest tier in the installed binary (X05). The P3 protocol constrains only "same model, same
  effort" across arms, so the cheapest tier is allowed.
- cwd: S/armA for A1 and A2, and S/armB for B1 and B2. Within an arm the pair shares one cwd, so the cwd line of the
  prompt is identical. Across arms the cwds differ, so no run can read the other arm's run cache.
- Project keys are predicted with tis_observed.project_key(resolved cwd): every non-alphanumeric character becomes
  `-` (UKDL T-PROJECT-KEY-PARTIAL-SANITIZE-001). They are recorded, but lookup is by session id across every project
  dir, so a wrong key can never read as zero reuse.
- Order and timing: A1, A2, B1, B2, strictly sequential. Each run launches the moment the previous process exits.
  Per-run timeout is 240 s, after which the process group is killed.
- Environment: the runner's environment minus every variable whose name starts with CLAUDE. The blocking names are
  refused before launch, never scrubbed: ANTHROPIC_* (any), plus BLOCKING_ENV = CLAUDE_CODE_OAUTH_TOKEN,
  CLAUDE_CONFIG_DIR and CLAUDE_CODE_USE_BEDROCK / _VERTEX / _FOUNDRY. Any ONE of them on its own sets env_check's
  `blocked`, which makes `--env-check` exit 3 and live() refuse at G1. scrubbed_env() raises rather than strip one.
  Every other CLAUDE* name is the launching session's coupling variable. Those are scrubbed and never block, so the
  executor's own session environment does not stop the run.
- Metric: `s = first_call_cache_read / first_call_context`, where context = input + cache_creation + cache_read. Both
  numbers come from SessionUsage fields of `tis_observed.read_session(transcript)`; cache_creation and its 5m/1h split
  come from the first call of `tis_observed.iter_calls`. The metric is rounded to 6 dp. Per arm, delta = s2 - s1.
  gap_run2 = s_B2 - s_A2, and delta_gap = delta_B - delta_A.
- Validity per run (any failure makes the run INVALID):
  - VR1: rc 0 and not timed out.
  - VR2: exactly one `<id>.jsonl` under /home/kobii/.claude/projects/*/ for the run's session id. The id is the
    pre-assigned one, falling back to the session_id in the run's own init event.
  - VR3: read_session state MEASURED, with first_call_context above 0.
  - VR4: entrypoint `sdk-cli` (the P3 protocol's per-run validity).
  - VR5: the first-call model contains `haiku` and equals A1's.
  - VR6: an init event, when present, has apiKeySource `none` or absent.
  - VR7: applies to run 2 only. The gap from run 1's last call ts to run 2's first call ts lies within [0, bound], and
    both fall on the same host-local date. An unknown timestamp fails VR7.
- TTL bound: 3300 s when run 1's first call wrote only 1h cache (ephemeral_1h above 0 and ephemeral_5m equal 0),
  otherwise 240 s.
- Manipulation and variance:
  - M1 (Arm B stripped MCP): PASS iff both B init events are present with an empty mcp_servers list and no tool name
    starting `mcp__`. FAIL if either shows one. UNKNOWN otherwise.
  - M2 (Arm A had MCP to vary): PASS iff A1 or A2 init lists at least one MCP server, in any status. FAIL iff both
    inits are present and list none. UNKNOWN otherwise.
  - vA: YES iff both A inits are present and their tools_sha256 or their sorted (name, status) server lists differ. NO
    iff both are present and equal. UNKNOWN otherwise.
- RULES (thresholds, fingerprinted): GAP_SUPPORT=0.3, B2_FLOOR=0.5, GAP_NULL=0.1, MISS_BAND=0.5, TTL_5M_BOUND_S=240,
  TTL_1H_BOUND_S=3300, REPLACEMENT_BUDGET=0.
  - Rationale: tools precede system in the request, so a tool-list change invalidates the whole cached prefix and
    reads near 0. The 0.3 gap and 0.5 floor leave room for partial reads when only a later section differs: system
    text, MCP instructions, or hook-injected first-turn context.
- Verdict, first match wins:
  - R1: a pre-check or live guard refused. UNJUDGED (BLOCKED: guard), with launches 0.
  - R2: any run INVALID, launches not 4, or the result incomplete. UNJUDGED (invalid: runs + rule ids).
  - R3: M1 not PASS. UNJUDGED (manipulation: Arm B MCP strip not confirmed).
  - R4: M2 not PASS. UNJUDGED (no MCP server in Arm A's default configuration; arms not differentiated).
  - R5: gap_run2 at least 0.3, s_B2 at least 0.5, and vA YES. SUPPORTED.
  - R6: absolute gap_run2 below 0.1, with s_A2 and s_B2 both below 0.5. REFUTED (both-miss: the miss persists with
    MCP stripped).
  - R7: absolute gap_run2 below 0.1 and vA YES. REFUTED (variance-without-miss: Arm A's MCP surface changed yet its
    run-2 reuse matched Arm B's).
  - R8: otherwise UNJUDGED, naming exactly one case. The cases are exclusive by range and are checked in this order:
    - similar-reuse-variance-not-observed: absolute gap_run2 below 0.1 (so vA is not YES and the two shares are not
      both below 0.5). Consistent with H, not a test of it;
    - B2-below-floor: gap_run2 at least 0.3 and s_B2 below 0.5;
    - gap-without-observed-variance: gap_run2 at least 0.3, s_B2 at least 0.5, and vA not YES;
    - intermediate-gap: gap_run2 from 0.1 up to below 0.3;
    - A-above-B: gap_run2 at or below -0.1.
- Replacement budget 0. ROADMAP criterion 2 fixes exactly 4 runs, so the P3 protocol's "max 2 replacements" is not
  used. A failed or timed-out run is recorded and the next run launches anyway. The runner writes S/LIVE-LATCH and
  raw/ab-live.json before the first launch, and refuses to start if either exists.
- Version-drift rule: all four runs use one sha256-pinned resolved binary. If the resolved version at the live run
  differs from the one recorded at pre-registration, record `claude_version_drift:`. The verdict is then scoped to the
  at-run version; drift does not invalidate the runs.
- Readout recovery rule: this is the only path to change ab_runner.py after pre-registration. If the runner fails
  AFTER launches (ab-live.json has `complete: false`), fix only the readout defect, adding a failing selftest case
  first. rules_fingerprint must stay byte-identical. Record `runner_post_registration_diff:` with the reason, then run
  `--readout ... --write`, which makes zero model calls.
- n_limit statement (canonical): "n=2 runs per arm, i.e. one run-2 reuse observation per arm. No variance estimate is
  possible. One back-to-back pair can neither bound how often MCP tool-list variance occurs nor exclude a one-off cache
  eviction. The verdict describes GEX44, the at-run claude version and this MCP configuration at the recorded live
  window, not the laptop."
- Scratch justification: S is outside /home/kobii/.claude and outside every repo. A scratch dir under this worktree
  would pull the repo's CLAUDE.md chain, its .claude settings and hooks, and a live git status into the system prompt.
  Each of those is a prefix variable unrelated to MCP, and git status would move between runs because a concurrent
  executor commits here. S is also outside other missions' dirs, owner-only, not a git repo, and uniquely named. It is
  left in place afterwards (OS-reclaimed /tmp), because its LIVE-LATCH is part of the rerun guard. No rm -rf is needed.

## Excerpt commands (Task 1; RES = the resolved binary path recorded in section 0, spelled literally)

Each writes a header `### Xnn <what>`, a `cmd:` line holding the exact pipeline, and one `> `-prefixed line appended to
P/raw/static-excerpts.txt. Each pipeline has the form `timeout 120 grep -a -o -E '<regex>' RES | head -n 1 | cut
-c1-420 | sed 's/^/> /' >> P/raw/static-excerpts.txt`, with these regexes:
- X01 authMethod ladder: `'"third_party";else if\([a-zA-Z_$]{1,3}==="claude\.ai"\).{0,300}'`
- X02 auth status field list: `'loggedIn:[a-zA-Z_$]{1,3},authMethod:[a-zA-Z_$]{1,3},apiProvider:.{0,330}'`
- X03 stream-json init fields: `'subtype:"init",cwd:[a-zA-Z_$]{1,3}\.cwd,session_id:.{0,330}'`
- X04 entrypoint rule: `'CLAUDE_CODE_ENTRYPOINT==="cli"&&[a-zA-Z_$]{1,3}\)[a-zA-Z_$]{1,3}\.set\("CLAUDE_CODE_ENTRYPOINT","sdk-cli"\).{0,40}'`
- X05 model tiers: `'"haiku":return 0;case"sonnet":return 1;case"opus":return 2;.{0,40}'`

If a regex matches nothing on the installed binary (version drift), stop and record the drift in section 0a. Do not
invent an excerpt. The Task 1 verify requires exactly five byte-verified lines.

## Harness behaviour (Phases 1-3, plus planning today)

- The session guard refuses shell forms it cannot prove stay inside the worktree. Refused: chained git commands, any
  `$( ... )` (including inside a for-loop or an echo), `( ... )` subshell groups, `[[ ... ]]`, `VAR=value cmd`
  prefixes, and env used as a wrapper.
- Accepted: `cd <dir> && <cmd>`, `timeout N <cmd>`, pipes, `<cmd> > file 2>&1; echo "rc=$?"`, `>> file` appends, and
  `python3 -c "..."`.
- Run each git command as its own plain Bash call from WT.
- The Bash tool kills a foreground call at 600 s. The live run therefore uses `run_in_background`.

## Commit protocol

1. Run `git add <explicit paths>` as its own call.
2. Write the message body to /tmp/claude-1000/cro-p04-ab/work/t<N>-msg.txt with the Write tool, ending with the
   attribution line your environment requires.
