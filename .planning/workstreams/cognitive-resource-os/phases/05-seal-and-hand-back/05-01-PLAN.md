## Harness behaviour (Phases 1-4)

- The session guard refuses shell forms it cannot prove stay inside the worktree: chained git commands, any `$( ... )`
  around git, `( ... )` subshells, `python3 -c` text that names git, `VAR=value cmd` prefixes, env as a wrapper.
- Accepted: one plain git command per Bash call from WT; `set -o pipefail; git ... | python3 ...` pipes (git output
  into a checker; checked at planning time); `git merge-base --is-ancestor A B; echo "rc=$?"`; `timeout N cmd`;
  `python3 <script>`. Run every git pipe with the `set -o pipefail; ` prefix, so a failing git fails the pipeline
  instead of being swallowed. The checker also treats empty stdin as FAIL, which covers the same case from its
  side.
- seal_check.py never runs git itself. Every git fact it checks arrives on stdin from a plain git command the guard
  can see. Do not add a subprocess git call to work around the guard. ROADMAP: never route around a refusing gate.
- The PreToolUse Write hook vetoes slop tokens, and the secret firewall vetoes credential shapes. Never type a
  docs slop token or a key-shaped string into any file. The selftest builds its slop fixture from SLOP_LISTS at run
  time.
