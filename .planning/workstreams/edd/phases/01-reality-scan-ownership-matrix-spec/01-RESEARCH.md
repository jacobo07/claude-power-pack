## Summary

The scan answers the roadmap's hypothesis ("the gap is generative OPERATORS feeding the existing obligation pipeline plus new closure-blocking classes") with two corrections that change the plan. First, **the existing obligation pipeline and the goal closure are two disjoint pipelines with no code path between them**: derived mission `Obligation`s (the only type with `consequence/parents/operator/closure_condition`) can be stored only in a per-root store that refuses writes once a goal is bound (`mission/store.py:92-94`), and goal closure only knows `GoalObligation`s registered by hand through `tools/gsd_x_goal.py oblige`. The mission-path completion effect (`ship:pre` gate) is off by default (`gsd_x_mission.enabled: false`) and hard-wired to the laptop's Windows paths; the mission path has no production verb that moves an obligation to SATISFIED (`mission.closure.satisfy` has no production caller). So Phase 3 needs a small additive bridge, not only operators. Second, **most EDD vocabulary has an existing, often doc-only, owner**: CLAE (sealed knowledge family: Completion Prosecutor, Reference Object, Incident-to-Probe, Human Oracle Boundary, Root-Cause Elevation + sibling campaigns + failure-to-immunity), DRK (decision records), the Constitutive Baseline Ratchet in `modules/tower` (live read/injection path, orphan promote and done-gate), the strength ladder (`modules/done_gate`), `rule_compiler/counterfactual.py`, `frontier_intelligence`, D2A, and the Goal spine planes. The repo's own history (UPAC map, 26 systems -> 0 GENUINELY_NEW; ~20 mega-corpus audits) predicts that very few matrix rows will survive HR-NOVELTY-001 as NEW; the genuinely absent pieces found so far are: lifecycle/ownership/projection/temporal/journey/negative-space OPERATORS, the Goal World Model, Earliest Preventable Point, a factory-repair disposition + Self-Evolution Debt as a closure-blocking class, Decision/Reference Frontier as closure-blocking classes, and blind counterfactual replay.

Measured baseline: the gsd_x subset runs in about 2 minutes on this host (all mission/goal/provider suites green; 5 pre-existing environmental reds listed in Section C); `modules/liveness/reachability.py` already exits 1 at HEAD (490 modules, 310 reachable, 180 orphan, 59 gate offenders), so "exit 0 for new modules" must be restated as "no NEW offender versus the recorded baseline". A latent defect was reproduced (`contract.py:205` reads `o.id`; the field is `identifier`) and is the first dogfood item for the Phase 4 factory-repair path.

**Primary recommendation:** Build the matrix with a discovered-denominator method (probe by mechanism, with a positive control, recording command + hit count), enforce it with a new `tools/test_edd_ownership_matrix.py` V-gate that fails when a row lacks a resolving producer AND consumer `path:line` or a NEW row lacks 13 answers, write D-01/D-02 as direct `DecisionRecord`s in `vault/decision_registry/records.jsonl` (not through the regex-driven kernel), and write `vault/specs/edd.md` with `covers:` entries that the repo's own `find_bound_spec` resolves STRONG.
