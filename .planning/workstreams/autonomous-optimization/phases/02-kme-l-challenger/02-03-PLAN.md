Design recorded for this plan (planner choice under CONTEXT discretion; reversibility: reversible, all in two files):
- The certificate is a small JSON file (no observer facts, no text): schema `kmep-cert/1`; question
  `{denominator, select, host, project_filter, cross_project, roots (realpaths), until}`; index
  `{path (realpath), schema_version, pattern_set, attr_version, attr_registry}`; keys `{parser:
  selection_parser_digest, metric: {population, D, E, F, G, H, I, L}}`; `selected {sessions, digest}` (sha256 of the
  sorted pairs); `uncovered {path: [size, mtime_ns]}` for in-scope `.jsonl` paths the index does not hold by its
  declared rules (`_preserved`, `_empty_shells` and other skipped shapes); `shadow {champion_selected, index_selected,
  agree}`; `certified_at`, `plane`, `command`. It binds code and question, not the index file identity, so a
  refreshed index is re-queried and still covered while the code digests hold.
- Invalidation keys and their closures:

| key | compared | closure on change | action |
|---|---|---|---|
| source watermark | index `files` (size, mtime_ns, offset) and certificate `uncovered` vs `os.stat` of in-scope files; new and vanished paths | the sessions owning the changed paths | stale sessions join the read set, classified in-process |
| parser version | `selection_parser_digest()` vs certificate | everything (the selection) | deopt `parser` |
| attribution version | index `meta.attr_version` vs `usage_index.ATTR_VERSION` vs certificate | everything | deopt `attribution` |
| pattern set | index `meta.pattern_set` vs live (population's own UNMEASURED reason) vs certificate | everything | deopt `population` / `pattern` |
| metric definition | `metric_digests()["population"]` vs certificate | everything | deopt `metric` |
| metric definition (pillar X) | `metric_digests()[X]` vs certificate | pillar X (recomputed every run in increment 1; nothing cached) | `metric_changed: [X]` in the path log, no deopt |

- `SELECTION_SOURCES`: file bytes of `tools/usage_index.py`, `wiki/tools/kme_token_audit.py`,
  `wiki/tools/kme_report.py`, plus the source text (`inspect.getsource`) of `kme_pillars.population` and
  `kme_pillars.make_keep`; digest = sha256 over sorted (name, bytes) pairs.
- `METRIC_DEFINITIONS`: per key a tuple of module-level constant names; digest of each = sha256 over the
  `ast.get_source_segment` text of those assignments, read from `wiki/tools/kme_pillars.py` (population, D..I) and
  `wiki/tools/kme_replay.py` (L) by `ast`, so neither module is imported for it. Starting lists (finalise from the code
  each observer reads, record the final lists in the SUMMARY): population `POP_FIELDS`, `WEIGHTS`; D `WEIGHTS`,
  `CPT_LO`, `CPT_HI`, `THRESHOLD`, `ESTIMATE_MODEL`, `CAVEATS`; E adds `STUB_PREFIX`, `WRITE_TOOLS`, `E_CLASSES`;
  F `INIT_RE`, `SKILL_BODY_PREFIX`; G `ESTIMATE_MODEL_G`, `G_CAVEATS`, `FALSIFY_RE`, `SEALED_RE`, `RETEST_RE`;
  H `H_DEFINITION`, `VERIFY_CMD_RE`, `VERIFIER_AGENT_RE`, `H_CAVEATS`; I `ESTIMATE_MODEL_I`, `I_CAVEATS`;
  L `ROLLOVER_GROWTH` and the constants `rank_result` reads.
