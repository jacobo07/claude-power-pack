## v5 design of record (decided here; RESEARCH Open Questions resolved)

Every change is additive. `CREATE TABLE IF NOT EXISTS` statements are appended to `SCHEMA`; new `files` columns are added
only by `_migrate_v5` (house rule of `connect()` lines 113-128: a reader never takes a write lock).

- `files` gains (tuple `_V5_COLUMNS`): `resolved TEXT, store TEXT, project TEXT, archived INTEGER, session_key TEXT,
  first_ts REAL, last_ts REAL, parse_errors INTEGER, error TEXT, v5_from INTEGER, head_sha TEXT, tail_sha TEXT,
  content_id TEXT, dup_of TEXT, pat_ver TEXT`. `resolved` is the transcript file's resolved path on this host
  (criterion 1 "realpath"), produced by `tools/tis_observed.py` (plan 02 adds `resolved_path`), never computed in
  usage_index: `tools/test_store_identity_consumers.py` V-SIC-UX-ONE-PRODUCER turns red when tools/usage_index.py contains
  any of the link-inspection or directory-listing tokens in its regex (lines 162-163), comments included; read that regex
  before writing usage_index code. `v5_from` = byte offset from which this file's v5 rows are complete:
  0 for a file first read under v5, the old offset for a legacy file that grows, NULL for a legacy file never re-read
  (typed UNMEASURED for every v5 fact, never "no tools").
- `call_files(k TEXT, file TEXT, ts REAL, model TEXT, inp INTEGER, cw INTEGER, cw5 INTEGER, cw1 INTEGER, cr INTEGER,
  out INTEGER, PRIMARY KEY(k, file))`: the occurrence view with that file's own usage values (per-field max on conflict,
  the champion's per-file dedup). It is order-independent, unlike `calls.file` (first writer wins, the measured 18-call
  gap). `calls` keeps its exact v4 semantics (global unique by `msgid|requestId`).
- `tool_events(file TEXT, tool_use_id TEXT, off INTEGER, ts REAL, tool TEXT, input_hash TEXT, input_bytes INTEGER,
  path TEXT, pat_hits TEXT, result_bytes INTEGER, result_chars INTEGER, is_error INTEGER, result_off INTEGER,
  PRIMARY KEY(file, tool_use_id))`. Result columns stay NULL until a tool_result is seen (never 0); the upsert never
  overwrites them.
- `user_hits(file TEXT, off INTEGER, ts REAL, pat_hits TEXT, PRIMARY KEY(file, off))` (sparse, only when a registered
  pattern hits; filled by plan 03).
- `file_cwds(file TEXT, cwd TEXT, first_off INTEGER, first_ts REAL, PRIMARY KEY(file, cwd))` (plan 03).
- `file_attribution(file TEXT, kind TEXT, name TEXT, role TEXT, n INTEGER, PRIMARY KEY(file, kind, name, role))`;
  kind `project|workstream`, role `home|touched`, name `<unattributed>` is the typed bucket (plan 03).
- `patterns(name TEXT PRIMARY KEY, regex TEXT, flags INTEGER, source TEXT, version TEXT)` (plan 03).
- meta keys: `v5_migration` `{at, files_opened: 0}`, `skipped_shapes`, `archived_rule`, `attr_registry`,
  `attr_version`, `pattern_set`.
- Content identity (Open Question 2): `content_id = sha256(f"{end}|{head_sha}|{tail_sha}")[:32]` where `head_sha` is the
  sha256 of the first complete raw line (fixed once written) and `tail_sha` the sha256 of the last complete raw line read,
  both from bytes `calls_from` already reads; `dup_of` = the smallest path of an equal-`content_id` group whose call-key
  sets are equal (plan 02). Merging never happens on `content_id` or `sessionId` alone.
- `_archived` (Open Question 3): files under `_archived/<project>/` are ingested into the v5 tables only (never into
  `calls`, `quota`, `prompts`, `spawns`, `subagents`), so every v4 reader keeps its exact v4 answer; population excludes
  them by default (plan 02 / 04).
- Odd shapes (Open Question 4): `_preserved`, `_empty_shells` and any other unmatched `*.jsonl` are not sessions; they are
  counted in `meta.skipped_shapes` (plan 02).
- Parity headline (Open Question 1): the occurrence view (call_files) is the gated number; the unique view, the keys
  shared with sessions outside the selection, and the v4 first-writer figure are reported beside it (plan 04 / 05).
- `result_chars` and `result_bytes` are both stored (Open Question 5).
