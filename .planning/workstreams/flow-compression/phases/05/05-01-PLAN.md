<objective>
Phase 5 / S5 "Terminal reconciliation" of workstream flow-compression. A worker that stops is not a mission that
ended, and a missing receipt must trigger reconciliation, never a false DONE (FC-07). Four defects are fixed and
one disposition is measured, all without a new lifecycle or state machine (FC-10).

Defects, each grounded in code read on this host (2026-10-24):
1. gsd_epoch.epochs closes an epoch only on mission_halted and mission_completed rows. Terminal transitions that
   carry other event names (slim_worker_finished, hold_settled, mission_superseded, unit_completed, unit_complete,
   owner_hold_released) leave the epoch open. Measured before the fix: 24 of 53 terminal missions that have
   epochs have their last epoch open. Open epochs inflate commit windows in certify (the commits() call over
   ep.start..ep.end) and every epoch-hour figure.
2. Three code paths derive "where the receipt is" and disagree: _receipt_path (chain unit receipt, else the stem
   convention), packet_receipt_path (the packet receipt: line, steward only) and the AMR and advance_unit stem
   builders. Measured: m-16bde3ea1101 (HALTED, "owner BLOCKED and budget: older than 24.0 h") has a packet whose
   receipt: line points to vault/specs/expected-completion.RECEIPT-E4a.json, which EXISTS; the mission layer looks
   for WU-E4a2-receipt.md, which does not, and reports "no receipt" while the steward sees one.
3. The slim_finished branch decides HALTED "no receipt" using only _receipt_path, so defect 2 becomes a false
   HALT, a renewal and steward accounting.
4. The 86 HALTED "no receipt" missions followed by steward_settled (45) or mission_renewed (34), and the "149 h",
   are quoted laptop-plane evidence; the definition of 149 h is not recoverable from any readable source. This
   plan builds the portable successor-check classifier (dispose) so the same measurement runs on any ledger.

Purpose: terminal truth. After this phase the epoch view, the receipt location, the reconciler verdict and the
disposition hours all agree with the ledger, and a stop is classified (RECOVERED_DONE, CONTINUATION, FAILED,
AMBIGUOUS) instead of being silently counted as lost time or silently counted as done.
Output: tools/mission_reconcile.py (new), edits to tools/gsd_epoch.py, tools/gsd_mission.py,
tools/mission_steward.py, the gate tools/test_s5_reconcile.py, STATE.md and RESUMPTION_FILE.md updates.
