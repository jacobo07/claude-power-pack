Premise corrections found by reading the code and the ledger before planning (the CONTEXT text is wrong on these; the plan follows the
code):
1. D-02 lists CPP_CCR_ADMISSION, CPP_MISSION_BOUNDED_RENEWAL and CPP_MISSION_RENEW as the S2-S6 switches. They are older mission
   features (CCR admission is observe by default and refuses only under enforce; bounded renewal is shadow by default; renewal_refusal
   returns a reason when CPP_MISSION_RENEW is off). The S2-S6 slice switches are the six listed in must_haves. Setting the three to
   "off" in the champion would delete a behaviour that existed before flow-compression and make the champion a strawman, so they are
   held at one recorded value in both arms and replayed on a separate renewal axis (Task 2). This keeps D-02's intent: a named toggle
   set over existing switches, applied by an env scope, restored after, no new switch.
2. plan_next is insensitive to every S2-S6 switch (none of them is read inside it). A champion-versus-challenger difference therefore
   cannot come from plan_next alone: S2, S3, S1, S4 and S6 are replayed through their own real functions, and plan_next is the seam
   only for the avoidable-idle evidence.
3. D-04 names ledger events (admission_refused, capital_exhausted, terminal-without-receipt) that this ledger does not contain, and
   there are zero "no receipt" halts on this host. Discovery therefore uses the real event kinds (see the table in Task 2), and a
   zero-population kind is reported as zero rows, not invented.
4. S3's digest normalisation and S5's reconcile have no kill switch of their own (S5 has only the annotation switch). For a slice with
   no switch the champion arm is reported UNMEASURED for the part it cannot turn off, never as "same as challenger".
5. D-01 says the replay "reconstructs the record fields plan_next needs" from the ledger. Ledger rows carry state, epoch, reason,
   worker and timestamps but not token_estimate, autocompact or the hold bodies, so a field the ledger cannot supply makes the call
   inputs_incomplete and the answer UNMEASURED, never a guessed default.
